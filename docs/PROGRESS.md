## 사용자 확정 요구: Canva 편집기 UI 일치

2026-11-06 사용자 지시: 아이들이 Canva에 익숙하므로 별도의 어린이용 UI로 재설계하지 않는다. 사진·배경·그리기·글씨와 슬라이드 관리에서 Canva와 같은 화면 배치, 메뉴 접근 경로, 선택·이동·크기 조절·글씨 편집 흐름을 필수 기준으로 삼는다. 첫 버전 기능에 도형·캐릭터·스티커 라이브러리를 추가한다. 차트는 제외한다. Phase 2 시험 화면의 배치는 최종 UI 기준이 아니다.

사용자가 지정한 한국어 소개 페이지의 25초 동영상에서 편집 화면을 직접 관찰했다. 관찰 기준과 미확인 부분은 docs/UI_REFERENCE.md를 따른다. 실제 계정의 편집기 조작은 아직 수행하지 않았다. 기존 계획의 도구·슬라이드 목록 위치와 이전 대화의 배치 제안은 영상에서 확인한 배치로 대체한다. 영상 밖의 세부 패널·조작은 UI_REFERENCE.md의 제품 결정으로 확정했다. 이 결정을 실제 Canva의 검증된 동작이라고 주장하지 않는다.

사용자가 Phase 3 시작을 지시했을 때 화면 기준은 제공되지 않았다. 그래서 코어를 먼저 구현하고 화면은 배치를 쉽게 바꿀 수 있는 임시 틀로 두었다. 확정된 UI_REFERENCE.md 기준은 Phase 4에서 화면에 반영했다.

## 2. 사용자 확인 절차와 결정

**확인 절차(약 15분).** PowerShell에서 아래 명령을 실행한다. 실행 정책 오류가 나면 `npm` 대신 `npm.cmd`를 쓴다.

```bash
npm.cmd run dev
```

1. 터미널에 나온 주소(보통 http://127.0.0.1:5173)를 연다. 슬라이드를 추가하고 상단 표시가 `변경 있음` → `저장됨`으로 바뀌는지 본다. 창을 닫았다가 다시 열어 작품 목록에 미리보기와 함께 있는지, 눌러서 이어 고칠 수 있는지 본다. 같은 작품을 다른 탭에서 열면 읽기 전용이 되는지, 작품을 지울 때 확인을 묻는지 본다.
2. 텍스트를 넣고 위쪽 글꼴 목록에서 6종을 바꿔 본다. 아이들에게 맞는 글꼴인지, 빼거나 더 넣을 것이 있는지 본다.
3. 텍스트 패널로 제목을 넣고 Windows 한글 입력기로 입력한다. 조합 중 Enter·Esc를 누르거나 다른 장을 눌러 글자가 사라지거나 겹치지 않는지, 글씨를 두 번 눌러 고칠 때 위치가 튀는지 본다. 요소 패널의 그림을 넣고, 업로드로 실제 사진을 넣고, 캡처한 화면을 Ctrl+V로 붙여 넣고, 배경을 바꿔 본다. 눌러서 끌고 손잡이로 크기를 바꾸고, 아래 슬라이드를 끌어 순서도 바꿔 본다.
4. 탐색기에서 `artifacts/phase5/editable.pptx`, `artifacts/phase5/image.pptx`, `artifacts/phase5/sample.pdf`를 더블클릭한다. PowerPoint의 복구 안내 창이 뜨면 알려 준다.

**결정 항목**

| 결정 | 필요한 입력 | 정하지 않으면 |
|---|---|---|
| 기본 글씨의 PPT 글꼴을 맑은 고딕 0.92배로 둘지 | 받는 PC가 대부분 한국어 Windows인지. 앱 화면과 줄이 40개 중 13개에서 다르게 나뉘는 것을 받아들일지 | 현재 결정대로 진행한다 |
| git 저장소 생성 | 생성 여부 | 코드 이력과 기준점이 없는 상태가 계속된다 |

## 3. 위험 요소와 검증 상태

- 확인됨: `npm run build`, `npm test` 전체. 공통 샘플 문서의 화면 표시 → 명령 → 취소 → 자동 저장 → 새로고침 복원 → 원본 내려받기 → 다른 프로필에서 열기 → PPT·PDF 출력. 대표 흐름 중 다른 주소로 나간 요청 0건, 브라우저 오류 0건.
- 화면과 출력 렌더의 평균 픽셀 차이: 장별 1.69, 0.84, 1.01, 0.04. Phase 4의 값(0.97, 0.51, 0.58, 0.00)보다 큰 것은 디자인 패널이 기본으로 열려 비교 화면이 작아졌기 때문이다.
- Phase 8 확인: 저장 예약·최대 대기·직렬 저장·늦은 저장·실패 재시도(`tests/contracts/autosave.spec.ts`). 재시작·강제 종료 복원, 오래된 revision 거부, 쓰기 오류 주입 시 `저장 실패`와 원본 내려받기, 사진만 기록되고 중단된 경우 이전 문서 유지와 고아 사진 정리, 공유 사진 보존, 다른 탭이 있을 때 지우기 거부, 같은 작품 둘째 탭 읽기 전용, 잠금 미지원 브라우저 읽기 전용, 사진·글씨·그림 작품의 새 프로필 왕복(`tests/e2e/home.spec.ts`). 작품 목록·읽기 전용·저장 실패 화면을 캡처로 눈으로 확인했다.
- 글꼴 확인: 6종 × 24·36·64px를 실제 PowerPoint로 렌더해 앱과 비교했다. 세로 중앙 차이 최대 0.035em, 첫 줄 폭 차이 ±4% 이내(1건 제외). 제외한 주아체 64px는 PowerPoint가 앱과 다른 낱말에서 줄을 나눈 경우로 보인다(폭 비율 0.797, 줄 수는 같음). 줄 나뉨 차이는 기본 글씨와 같은 자동 줄바꿈 제약이다. 배포본(`dist`)에서 8개 글꼴·굵기를 WOFF2만으로 읽었고 실패·외부 요청 0건이다.
- 300획 문서에서 끌기 중 프레임 간격 p95 16.8ms(개발 PC). 조작 중인 요소만 별도 레이어로 그린다.
- 실제 앱 경로의 20장×사진 3장(합성 사진 60장, 저장 45.6MB, 개발 PC): 사진 1장 입력 약 164ms, 장 전환 약 65ms. 브라우저 전체 메모리는 시작 367MB, 20장을 넘긴 뒤 524MB, 출력 후 692MB. 편집용 PPT 45.7MB·5초, 모양 그대로 PPT 7.8MB·2.9초, PDF 8.2MB·1.8초.
- 라이브러리 그림·사진·배경을 함께 쓴 작품의 원본 저장 → 그림 파일을 막은 새 프로필에서 열기 → 내용 일치, PowerPoint 2종 열기와 PDF 렌더를 눈으로 비교했다.
- 실제 PowerPoint(COM)로 편집용·모양 그대로 PPT를 열어 4장 모두 렌더하고 글씨 줄을 읽었다. 사진·획·글씨 순서가 유지됨을 눈으로 확인했다(`scripts/phase3-montage.py`, `npm test`가 지우므로 PowerPoint 스크립트 뒤에 다시 만든다).
- PPT 세로 위치: 줄 간격 1~2, 글씨 크기 24·36·64px에서 측정해 줄 간격에 따라 보정한다. 보정 후 결과는 PHASE2_RESULTS.md §4에 있다.
- 시험 주의: `tests/contracts/autosave.spec.ts`는 실제 타이머를 5~30ms 여유로 쓴다. 느린 PC에서 이 파일만 실패하면 회귀로 단정하지 말고 먼저 다시 돌려 본다.
- 측정 범위 밖: 사람이 직접 쓴 자동 저장, 실제 저장 공간 부족, Chromium 외 브라우저의 잠금, 실제 한글 입력기, 물리 터치, iPad, RAM 8GB 기기, 실제 사진, 실제 Canva 편집기와의 일치.
- 편의 결정: 저장 작품이 있으면 작품 목록에서 시작하고, 없으면 새 작품으로 바로 들어간다. 새로고침하면 같은 탭에서 보던 작품으로 돌아온다. 손대지 않은 새 작품은 저장하지 않아 목록에 남지 않는다. 다른 작품으로 넘어갈 때 묻지 않고 자동 저장하며, 실패할 때만 묻는다. 잠금 미지원 브라우저는 읽기 전용으로 연다. 고아 사진은 작품 목록에 들어올 때 다른 탭이 없으면 정리한다. Esc와 다른 곳 누르기는 입력을 확정한다(입력 취소는 입력 중 Ctrl+Z). Esc로 끝내면 글씨가 선택된 채로 남고, 빈 곳을 눌러 끝내면 선택도 풀린다. 입력 중 되돌리기 버튼은 입력을 확정한 뒤 되돌린다. 창 폭 1200px 이상이면 디자인 패널을 연 채로 시작하고, 그보다 좁으면 닫고 시작한다. 불투명한 입력 사진은 JPEG(품질 0.9), 투명한 사진만 PNG로 저장한다. 안내 문구는 슬라이드를 덮지 않도록 설정 줄 오른쪽에 둔다. Backspace도 Delete와 같이 선택 요소를 지운다(되돌릴 수 있음). 슬라이드 끌어 옮기기는 마우스만 지원하고 터치는 장 메뉴를 쓴다.
- 알려진 제약: 번들 크기 경고(출력 라이브러리 지연 로딩 미적용). 배포 결과 26MB. `.woff`는 빌드 때 지우고 `.woff2`만 남기며, 글꼴은 글자 묶음 단위로 필요할 때만 받는다. `.canvacraft`를 처리하지 않는 정적 호스트 설정은 Phase 10에서 확인한다. 잘린 JPEG는 브라우저가 앞부분만 디코딩해 들어올 수 있다. 도형 색 변형 파일은 manifest에 해시가 없어 형식·크기·라이선스만 확인한다.

## 5. 다음 AI에게

- 화면 기준은 UI_REFERENCE.md다. 차트는 구현하지 않는다. 내장 그림의 형식은 [ASSET_LIBRARY_READY.md](ASSET_LIBRARY_READY.md)에 있다.
- Phase 4~8은 매번 `tests/e2e/flow.spec.ts`가 계속 통과하는지 확인한다. 새 필드가 생기면 `scripts/make-fixture.mjs`와 샘플 문서를 먼저 고친다.
- Konva 끌기·Transformer·hit 그래프를 쓰지 않는다. 포인터는 `SelectionLayer`가 받아 논리 좌표로 바꾸고, 조작 중 값은 `preview`로만 보관하다가 손을 뗄 때 명령을 한 번 보낸다. Konva scale을 쓰지 않으므로 값이 누적되지 않는다.
- 글씨 입력은 `src/editor/TextEditor.tsx`다. 값을 React로 되써넣지 않는다. 입력을 끝내는 일은 `flushEdit`로만 하며, 조합 중이면 compositionend를 기다린다. 문서를 바꾸는 다른 조작도 먼저 `flushEdit`를 거친다.
- 사용자 사진은 `importAsset`으로 항상 다시 만들고, 내장 그림은 원본 바이트를 유지한다. 내장 그림을 재인코딩하면 PNG의 라이선스 정보가 사라지므로 두 경로를 합치지 않는다.
- 글꼴을 더 넣을 때는 `src/domain/limits.ts`(FONT_IDS, BOLD_FONT_IDS), `src/rendering/text/fonts.ts`(등록표), `src/app/main.tsx`(CSS import), `public/licenses`, `docs/asset-licenses.md`를 함께 고친다. 대응값은 `tests/phase2/fontfit.spec.ts`로 잰다(`-g "한글 폭"`, `-g 측정용` → `pwsh -NoProfile -File scripts/phase2-powerpoint.ps1 -Dir artifacts/fontfit` → `-g 위치`).
- 저장은 `createAutosave`가 작품당 한 번에 하나만 돌린다. 작품 전환·원본 열기는 `afterSaved`를 거친다. 저장 잠금 순서는 catalog → 작품이고, 공유 잠금을 쥔 채 배타 잠금을 기다리지 않는다. 고아 사진 삭제는 배타 catalog 안에서만 한다.
- 사용자에게 Phase 2 전체 완료라고 보고하지 않는다. 문서 분담이나 병렬 작업을 시작하지 않는다.
- `public/backgrounds-illustrated`(이미지 생성 도구로 만든 배경, 시험 1장)는 GPT가 작업 중으로 보이며 인계 문서가 없어 앱에 연결하지 않았다. 배포 결과에는 복사된다.
- 시험 시 Playwright로 큰 파일을 숫자 배열로 넘기지 않는다. 약 10MB 파일 두 개에서 실행 컨텍스트가 끊겼고 base64로 바꾸자 통과했다.
