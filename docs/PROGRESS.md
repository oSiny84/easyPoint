- 영상 미리보기의 **빠른 조각 깜빡임과 스페이스 재생을 고쳤다**(2026-11-10 사용자 보고, 커밋 c4af38e). 한 영상을 두 번 잘라 가운데만 2배로 하면 그 조각으로 넘어갈 때 화면이 검게 깜빡였다. 이제 깜빡이지 않는다. 스페이스는 조각·단추·빠르기 상자·배율 막대를 마우스로 누른 뒤에도 재생·일시정지를 바꾼다(전에는 그 단추를 다시 누르거나 목록을 열었다). 글자를 넣는 칸, 창·메뉴 안, Tab으로 옮겨 간 단추에서는 원래 동작을 둔다. 깜빡임의 원인은 `<video>`가 재생을 시작하며 잠깐 멈춰 있는 시간을 어긋남으로 센 것이다. 원본 시간으로 재서 2배 조각에서는 2배로 보였고, 150ms를 넘으면 위치를 다시 맞췄는데 다시 맞춰도 같은 지연이 생겨 되풀이됐으며, 맞추는 동안에는 검게 그렸다. 이제 시작 지연을 기준으로 삼아 그 뒤 150ms 넘게 벗어날 때만 다시 맞추고(`src/video/previewSync.ts`), 재생 중에는 검은 화면 대신 마지막 영상 프레임을 둔다(계약 §8 미리보기). 개발 PC에 블루투스 이어폰이 연결된 상태(소리 출력 지연 0.29초)에서 시험 영상으로 쟀다: 고치기 전 검은 화면 9회·다시 맞춤 9회(2배·4배 모두, 보통 빠르기 조각에서도 생김) → 고친 뒤 0회·0회. **프리릴리스 v0.0.4에는 들어 있지 않다.** 남은 것: 소리가 늦게 나가는 장치에서는 조각이 바뀔 때마다 영상이 0.3초쯤 멈췄다 움직이고 그만큼 늦게 따라간다(검게 깜빡이지는 않는다. 내보낸 파일과는 관계없다). 사용자가 본 깜빡임이 어떤 소리 장치에서 났는지와 실제 휴대폰 영상은 확인하지 않았다.

- 영상 편집기 **V6(움직이는 밈·효과음·소리)를 구현했다**(2026-11-09). 밈 패널(찾기·분류 칩·카드)에서 움직이는 스티커와 소리 든 밈 영상을 누르거나 끌어다 놓아 넣고, 모서리로 비율을 지키며 크기를 바꾸고, 밈 소리를 끄고 켠다. 같은 시각 밈 영상 2개·스티커 4개 상한은 안내로 막는다. 소리 패널에서 영상 원래 소리(끄기·작게·크게), 배경음악, 음악 크기를 고른다. 미리보기는 스티커 프레임을 ImageDecoder로 그때그때 풀고, 밈 영상은 숨긴 `<video>`로, 효과음·배경음악은 Web Audio로 같은 시계에 맞춘다. **밈·소리는 직접 만든 자리 표시 자산(스티커 4·밈 영상 2·효과음 3·음악 2)이다.** 실제 자산 출처는 사용자 결정이 필요하다([asset-licenses.md](asset-licenses.md)). 실행 파일·배포 서버가 `.webp`·`.webm`·`.wav`·`.mp4` 형식을 알려 주게 했다(계약 V8 예정에서 앞당김).
- 영상 편집기 **V5(자막)를 구현했다**(2026-11-09). 자막 패널의 보통·크게·띠 없음으로 재생 막대 위치부터 3초 보이는 자막을 넣고, 미리보기 위에서 두 번 눌러 고치며(한글 조합 규칙은 슬라이드와 같다), 끌기·크기 조절·서식(글꼴·크기·굵게·색·정렬·띠)·보이는 시간 −/+·지금부터·타임라인 막대 끌기로 바꾼다. 영상 끝을 넘으면 먼저 줄이고 알린다. 미리보기는 자막을 슬라이드와 같은 줄 배치로 미리 그린 그림으로 겹치며, 보이는 시각이 startMs ≤ t < 끝 규칙과 같음을 시험했다. `geometry.ts` 이동·글씨 크기·가운데 놓기가 캔버스 크기를 받는다(슬라이드 시험 무수정 통과). npm test 395 통과.
- 영상 편집기 **V4(영상 넣기·미리보기·타임라인·자르기)를 구현했다**(2026-11-09). 영상 패널의 `영상 가져오기`나 끌어놓기로 MP4·MOV·WebM을 넣으면 Worker가 형식·해독 가능 여부를 확인하고 저장소에 복사하면서 조각 해시를 계산한다(파일 이름은 남기지 않는다). 미리보기는 숨긴 `<video>` 2개를 AudioContext 시계에 맞춰 번갈아 재생하며, 시험 영상을 이어 붙이고 잘라 재생하면 조각 경계 간격이 자른 자리 100~134ms, 다른 영상 사이 50~66ms였다(평소 프레임 간격 34ms, 목표 200ms 이내, 4회). 타임라인에서 재생 막대를 옮기고, 여기서 자르기·양 끝 끌어 다듬기·앞뒤 옮기기·조각 소리 끄기·지우기를 하며 각각 되돌리기 한 번에 돌아온다. 배포본 CSP에 `media-src 'self' blob:`·`worker-src 'self'`를 넣었다(계약은 V8 예정이었으나 미리보기가 생겨 앞당김). **실제 휴대폰 영상(MOV·HEVC·회전·편집 목록)은 아직 시험하지 않았다.** 자막·밈은 V5·V6이라 미리보기에 아직 그려지지 않는다.
- 영상 편집기 **V3(시작 화면·영상 문서·저장 틀)를 구현했다**(2026-11-09). 앱을 열면 시작 화면(슬라이드 만들기 / 영상 만들기 + 두 종류를 섞은 최근 작품 6개)이 나오고, 새로고침하면 쓰던 작품의 편집기로 돌아온다(기억 값은 `{kind,id}` JSON, 옛 문자열은 슬라이드). 영상 쪽은 작품 목록·편집기 틀(상단 바·도구 4개·미리보기 자리·조각 띠)·자동 저장·원본(`.canvavideo`) 열기·저장·지우기까지 동작한다. 문서·명령 18개·취소·겹침 요소 따라가기·동시 밈 상한·검사, IndexedDB `canvacraft-video` + OPFS 바이트 저장, 자체 STORE ZIP(ZIP64 포함)을 넣었다. 슬라이드 저장소는 공통 틀(`src/state/history.ts`)로 일반화했고 슬라이드 계약 시험은 고치지 않고 통과한다. **아직 영상을 직접 넣을 수 없다**(가져오기·미리보기·타임라인 조작은 V4). 영상 편집기 코드는 시작 화면에서 타일을 누를 때 불러온다.

**위험 요소**

- 브라우저 저장소는 사용자가 사이트 데이터를 지우거나 공용 PC가 초기화되면 사라진다. 영구 보관을 요청하지만 보장되지 않는다. 작품 목록 화면에서 원본을 내려받도록 안내한다.
- 글꼴을 고른 글씨는 편집용 PPT에서 모양이 달라진다. 내려받기 화면과 완료 안내에서 알리지만 아이들이 놓칠 수 있다.

- 성능 수치는 고성능 개발 PC와 합성 사진 기준이다. RAM 8GB 기기에서 확인하지 않았다.

**결론**

슬라이드는 만들고, 저절로 저장되고, 다시 열고, 출력하는 흐름이 동작한다. 발표까지 연결됐고 배포 패키지를 만들 수 있다. 남은 것은 사람·기기 확인과 공개 배포 결정이다. 영상은 시작 화면에서 들어가 영상을 넣고 자르고 자막·밈·음악을 넣어 MP4로 내보내기까지 된다. 남은 것은 실제 휴대폰 영상·플레이어·YouTube 확인, 실제 밈 그림, 8GB PC 확인이다. 영상 편집기가 든 실행 파일은 프리릴리스 `v0.0.3`이다.

## 사용자 확정 요구: Canva 편집기 UI 일치

2026-11-06 사용자 지시: 아이들이 Canva에 익숙하므로 별도의 어린이용 UI로 재설계하지 않는다. 사진·배경·그리기·글씨와 슬라이드 관리에서 Canva와 같은 화면 배치, 메뉴 접근 경로, 선택·이동·크기 조절·글씨 편집 흐름을 필수 기준으로 삼는다. 첫 버전 기능에 도형·캐릭터·스티커 라이브러리를 추가한다. 차트는 제외한다. Phase 2 시험 화면의 배치는 최종 UI 기준이 아니다.

사용자가 지정한 한국어 소개 페이지의 25초 동영상에서 편집 화면을 직접 관찰했다. 관찰 기준과 미확인 부분은 docs/UI_REFERENCE.md를 따른다. 실제 계정의 편집기 조작은 아직 수행하지 않았다. 기존 계획의 도구·슬라이드 목록 위치와 이전 대화의 배치 제안은 영상에서 확인한 배치로 대체한다. 영상 밖의 세부 패널·조작은 UI_REFERENCE.md의 제품 결정으로 확정했다. 이 결정을 실제 Canva의 검증된 동작이라고 주장하지 않는다.

사용자가 Phase 3 시작을 지시했을 때 화면 기준은 제공되지 않았다. 그래서 코어를 먼저 구현하고 화면은 배치를 쉽게 바꿀 수 있는 임시 틀로 두었다. 확정된 UI_REFERENCE.md 기준은 Phase 4에서 화면에 반영했다.

- 측정 범위 밖: 프로젝터·터치 기기의 발표, 한쇼·Google Slides·PowerPoint 웹, 출력 중 메모리, 실제 저장 공간 부족, Chromium 외 브라우저의 잠금, 물리 터치, iPad, RAM 8GB 기기, 실제 사진이 많은 큰 문서, 실제 Canva 편집기와의 일치.
- 편의 결정: 발표는 지금 보던 장에서 시작하고, 마지막 장에서 더 넘기면 끝나지 않고 멈춘다. 화면 왼쪽 4분의 1을 누르면 앞 장, 나머지는 다음 장이다. 조작 줄은 3초 뒤 숨는다. 파일을 만드는 동안에는 발표를 시작할 수 없고, 작품을 떠나면 만들던 파일은 취소된다. 앱은 항상 시작 화면에서 시작하고(영상 V3부터), 슬라이드 만들기를 누르면 작품 목록이 나온다. 새로고침하면 같은 탭에서 보던 작품으로 돌아온다. 손대지 않은 새 작품은 저장하지 않아 목록에 남지 않는다. 다른 작품으로 넘어갈 때 묻지 않고 자동 저장하며, 실패할 때만 묻는다. 잠금 미지원 브라우저는 읽기 전용으로 연다. 고아 사진은 작품 목록에 들어올 때 다른 탭이 없으면 정리한다. Esc와 다른 곳 누르기는 입력을 확정한다(입력 취소는 입력 중 Ctrl+Z). Esc로 끝내면 글씨가 선택된 채로 남고, 빈 곳을 눌러 끝내면 선택도 풀린다. 입력 중 되돌리기 버튼은 입력을 확정한 뒤 되돌린다. 창 폭 1200px 이상이면 배경 패널을 연 채로 시작하고, 그보다 좁으면 닫고 시작한다. 불투명한 입력 사진은 JPEG(품질 0.9), 투명한 사진만 PNG로 저장한다. 안내 문구는 슬라이드를 덮지 않도록 설정 줄 오른쪽에 둔다. Backspace도 Delete와 같이 선택 요소를 지운다(되돌릴 수 있음). 슬라이드 끌어 옮기기는 마우스만 지원하고 터치는 장 메뉴를 쓴다. 패널 그림 끌어 넣기도 터치에서는 시작하지 않는다. 터치는 패널 스크롤에 쓰므로 누르기로 넣는다.
- 알려진 제약: 지운 사진도 작품의 사진 용량 한도(200MiB, 1000개)에 계속 포함된다. 넣은 사진 목록에서 지우는 기능은 없다. 번들 크기 경고가 남아 있다(첫 스크립트 756KB, 출력 도구는 내려받을 때 불러온다). 배포 결과 24MB. `.woff`는 빌드 때 지우고 `.woff2`만 남기며, 글꼴은 글자 묶음 단위로 필요할 때만 받는다. `.canvacraft`를 막는 호스트에서는 템플릿이 열리지 않는다([RELEASE.md](RELEASE.md)). 잘린 JPEG는 브라우저가 앞부분만 디코딩해 들어올 수 있다. 도형 색 변형 파일은 manifest에 해시가 없어 형식·크기·라이선스만 확인한다.

## 5. 다음 AI에게

- 화면 기준은 UI_REFERENCE.md다. 차트는 구현하지 않는다. 내장 그림의 형식은 [ASSET_LIBRARY_READY.md](ASSET_LIBRARY_READY.md)에 있다.
- Phase 4~8은 매번 `tests/e2e/flow.spec.ts`가 계속 통과하는지 확인한다. 새 필드가 생기면 `scripts/make-fixture.mjs`와 샘플 문서를 먼저 고친다.
- Konva 끌기·Transformer·hit 그래프를 쓰지 않는다. 포인터는 `SelectionLayer`가 받아 논리 좌표로 바꾸고, 조작 중 값은 `preview`로만 보관하다가 손을 뗄 때 명령을 한 번 보낸다. Konva scale을 쓰지 않으므로 값이 누적되지 않는다.
- 글씨 입력은 `src/editor/TextEditor.tsx`다. 값을 React로 되써넣지 않는다. 입력을 끝내는 일은 `flushEdit`로만 하며, 조합 중이면 compositionend를 기다린다. 문서를 바꾸는 다른 조작도 먼저 `flushEdit`를 거친다.
- 사용자 사진은 `importAsset`으로 항상 다시 만들고, 내장 그림은 원본 바이트를 유지한다. 내장 그림을 재인코딩하면 PNG의 라이선스 정보가 사라지므로 두 경로를 합치지 않는다.
- 실행 파일의 연결 번호 47831은 바꾸지 않는다. 브라우저는 주소별로 작품을 저장하므로 바꾸면 아이의 작품이 보이지 않는다. 개발 서버(5173 등)의 작품도 실행 파일에서는 보이지 않는다.
- 글꼴을 더 넣을 때는 `src/domain/limits.ts`(FONT_IDS, BOLD_FONT_IDS), `src/rendering/text/fonts.ts`(등록표), `src/app/main.tsx`(CSS import), `public/licenses`, `docs/asset-licenses.md`를 함께 고친다. 대응값은 `tests/phase2/fontfit.spec.ts`로 잰다(`-g "한글 폭"`, `-g 측정용` → `pwsh -NoProfile -File scripts/phase2-powerpoint.ps1 -Dir artifacts/fontfit` → `-g 위치`).
- 발표는 `renderSlide`로 스냅샷을 그리며 문서를 바꾸지 않는다. 고해상도 캔버스는 지금 장과 앞뒤 장만 유지한다. 키 입력은 `Presenter`가 창 캡처 단계에서 끊어 편집 단축키가 닿지 않게 한다.
- 저장은 `createAutosave`가 작품당 한 번에 하나만 돌린다. 작품 전환·원본 열기는 `afterSaved`를 거친다. 저장 잠금 순서는 catalog → 작품이고, 공유 잠금을 쥔 채 배타 잠금을 기다리지 않는다. 고아 사진 삭제는 배타 catalog 안에서만 한다.
- 사용자에게 Phase 2 전체 완료라고 보고하지 않는다. 문서 분담이나 병렬 작업을 시작하지 않는다.
- 그림 배경은 1672×941이라 정확한 16:9가 아니다. 화면과 출력은 가운데 맞춰 자르고, 편집용 PPT는 JPEG로 다시 만든다. 새 그림을 넣으면 `illustrated-background-pipeline/thumbnails.cjs`로 미리보기를 만든다. 원본 PNG를 패널 카드에 쓰면 카드를 그리는 데만 약 39MB를 받는다.
- `dist/index.html`의 보안 정책은 `scripts/prune-dist.mjs`가 넣는다. 외부 자원을 새로 쓰거나 글꼴을 `data:`로 넣으면 배포본에서만 막힌다. 그래서 `npm run test:release`가 개발 서버 시험과 별도로 필요하다.
- 시험 시 Playwright로 큰 파일을 숫자 배열로 넘기지 않는다. 약 10MB 파일 두 개에서 실행 컨텍스트가 끊겼고 base64로 바꾸자 통과했다.
