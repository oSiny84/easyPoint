## 3분 요약

**현재 상태**

- Phase 10의 자동 점검과 산출물을 마쳤다. 배포본으로 대표 시나리오 7개를 통과했고 결과는 [통합 시험 보고서](INTEGRATION_REPORT_2026-11-06.md)에 있다. 사용 설명과 배포 패키지 절차도 만들었다. **어린이 사용성 관찰은 미실시이고 공개 배포도 하지 않았다.**
- Phase 9를 구현하고 자동 시험을 통과했다. 상단 발표 버튼으로 전체 화면 발표(이전·다음·끝내기)를 하고, 내려받기 창에서 진행률·취소·다시 받기·경고를 볼 수 있다. 사용자가 발표와 패널 그림 끌어 넣기를 실제 브라우저에서 확인했다(2026-11-06).
- Phase 8을 구현하고 자동 시험을 통과했다. 이제 저장 버튼 없이 변경 1초 뒤(연속 편집 중 최대 5초) 자동 저장되고, 작품 목록 화면에서 여러 작품을 열고 지울 수 있다. 저장 실패·탭 강제 종료·다른 탭 동시 열기도 처리한다.
- 글꼴을 6종으로 늘렸다(기본 글씨, 주아체, 도현체, 감자꽃체, 나눔손글씨 펜, 개구쟁이체). 앱 화면·PDF·모양 그대로 PPT에는 그대로 나오고, 편집용 PPT에서는 맑은 고딕으로 바뀐다.
- 사용자가 실제 환경에서 확인했다(2026-11-06): 내려받은 PPT·PDF가 복구 안내 없이 열림, 한글 입력기 조합 중 Enter·Esc 정상, 실제 카메라 사진 가져오기 정상.
- 사용자가 자동 저장, 다시 열기, 둘째 탭 읽기 전용, 글꼴 변경을 실제 브라우저에서 확인했다(2026-11-06). 실제 저장 공간 부족은 확인하지 않았다.
- 이번 배치는 UI_REFERENCE.md와 맞춘 것이며 실제 Canva 편집기와 일치하는지 검증한 것은 아니다.
- Phase 2의 사람·기기 확인 8개는 아직 미검증이다.
- git 저장소가 있다(origin: easyPoint, 2026-11-06 16시경 커밋 `phase8`). Phase 9·10 변경은 작업 브랜치 `phase9-10`에 커밋했고 push는 하지 않았다. 배포는 하지 않았다.

**진행률**

- 10단계 중 Phase 10의 자동 점검까지 왔다. 사람이 해야 할 확인이 남았다. Phase 2 수동 확인 8개는 남아 있다.
- 계약의 편집 명령 18개 중 18개 모두 화면에 연결됐다.
- 도구 패널 6개가 모두 동작한다. 화면에서 준비 중으로 남은 것은 없다.

**다음 액션**

1. `phase9-10` 브랜치를 main에 합칠지, push할지 결정 (사용자)
2. 터치 기기 확인, 어린이 사용성 관찰 (사용자, 보호자·교사 입회)
3. 공개 배포 여부, 웹 호스트 선택, 이름·화면 권리 검토 (사용자, [RELEASE.md](RELEASE.md))
4. RAM 8GB 기기에서 사진이 많은 문서 확인 (사용자)

**위험 요소**

- 브라우저 저장소는 사용자가 사이트 데이터를 지우거나 공용 PC가 초기화되면 사라진다. 영구 보관을 요청하지만 보장되지 않는다. 작품 목록 화면에서 원본을 내려받도록 안내한다.
- 글꼴을 고른 글씨는 편집용 PPT에서 모양이 달라진다. 내려받기 화면과 완료 안내에서 알리지만 아이들이 놓칠 수 있다.
- 공개 배포를 한다면 Canva와 비슷한 배치와 CanvaCraft라는 이름의 권리 문제를 먼저 확인해야 한다. 아직 검토하지 않았다.
- 성능 수치는 고성능 개발 PC와 합성 사진 기준이다. RAM 8GB 기기에서 확인하지 않았다.

**결론**

만들고, 저절로 저장되고, 다시 열고, 출력하는 흐름이 동작한다. 발표까지 연결됐고 배포 패키지를 만들 수 있다. 남은 것은 사람·기기 확인과 공개 배포 결정이다.

## 사용자 확정 요구: Canva 편집기 UI 일치

2026-11-06 사용자 지시: 아이들이 Canva에 익숙하므로 별도의 어린이용 UI로 재설계하지 않는다. 사진·배경·그리기·글씨와 슬라이드 관리에서 Canva와 같은 화면 배치, 메뉴 접근 경로, 선택·이동·크기 조절·글씨 편집 흐름을 필수 기준으로 삼는다. 첫 버전 기능에 도형·캐릭터·스티커 라이브러리를 추가한다. 차트는 제외한다. Phase 2 시험 화면의 배치는 최종 UI 기준이 아니다.

사용자가 지정한 한국어 소개 페이지의 25초 동영상에서 편집 화면을 직접 관찰했다. 관찰 기준과 미확인 부분은 docs/UI_REFERENCE.md를 따른다. 실제 계정의 편집기 조작은 아직 수행하지 않았다. 기존 계획의 도구·슬라이드 목록 위치와 이전 대화의 배치 제안은 영상에서 확인한 배치로 대체한다. 영상 밖의 세부 패널·조작은 UI_REFERENCE.md의 제품 결정으로 확정했다. 이 결정을 실제 Canva의 검증된 동작이라고 주장하지 않는다.

사용자가 Phase 3 시작을 지시했을 때 화면 기준은 제공되지 않았다. 그래서 코어를 먼저 구현하고 화면은 배치를 쉽게 바꿀 수 있는 임시 틀로 두었다. 확정된 UI_REFERENCE.md 기준은 Phase 4에서 화면에 반영했다.

## 3. 위험 요소와 검증 상태

- 확인됨: `npm run build`, `npm test` 전체. 공통 샘플 문서의 화면 표시 → 명령 → 취소 → 자동 저장 → 새로고침 복원 → 원본 내려받기 → 다른 프로필에서 열기 → PPT·PDF 출력. 대표 흐름 중 다른 주소로 나간 요청 0건, 브라우저 오류 0건.
- 화면과 출력 렌더의 평균 픽셀 차이: 장별 1.69, 0.84, 1.01, 0.04. Phase 4의 값(0.97, 0.51, 0.58, 0.00)보다 큰 것은 디자인 패널이 기본으로 열려 비교 화면이 작아졌기 때문이다.
- Phase 8 확인: 저장 예약·최대 대기·직렬 저장·늦은 저장·실패 재시도(`tests/contracts/autosave.spec.ts`). 재시작·강제 종료 복원, 오래된 revision 거부, 쓰기 오류 주입 시 `저장 실패`와 원본 내려받기, 사진만 기록되고 중단된 경우 이전 문서 유지와 고아 사진 정리, 공유 사진 보존, 다른 탭이 있을 때 지우기 거부, 같은 작품 둘째 탭 읽기 전용, 잠금 미지원 브라우저 읽기 전용, 사진·글씨·그림 작품의 새 프로필 왕복(`tests/e2e/home.spec.ts`). 작품 목록·읽기 전용·저장 실패 화면을 캡처로 눈으로 확인했다.
- 글꼴 확인: 6종 × 24·36·64px를 실제 PowerPoint로 렌더해 앱과 비교했다. 세로 중앙 차이 최대 0.035em, 첫 줄 폭 차이 ±4% 이내(1건 제외). 제외한 주아체 64px는 PowerPoint가 앱과 다른 낱말에서 줄을 나눈 경우로 보인다(폭 비율 0.797, 줄 수는 같음). 줄 나뉨 차이는 기본 글씨와 같은 자동 줄바꿈 제약이다. 배포본(`dist`)에서 8개 글꼴·굵기를 WOFF2만으로 읽었고 실패·외부 요청 0건이다.
- Phase 9 확인: 발표의 이동·끝내기·전체 화면 해제, 전체 화면을 쓸 수 없을 때, 발표 중 편집 단축키·붙여넣기 차단, 20장 빠르게 넘기기, 사진을 못 읽는 장, 읽기 전용 탭(`tests/e2e/present.spec.ts`). 출력 도중 취소 후 다시 받기와 출력 중 편집 분리도 같은 파일에 있다. PowerPoint 16.0(COM)으로 편집용 파일의 글씨를 고치고 사진을 옮겨 저장한 뒤 다시 열어 값이 유지됨을 확인했고, 편집용·모양 그대로 4장을 렌더했다. 앱·PowerPoint·PDF 4장을 나란히 놓고 배경·사진·글씨·획 순서와 PDF 쪽 순서가 같음을 눈으로 확인했다(`artifacts/phase9/montage.png`).
- 300획 문서에서 끌기 중 프레임 간격 p95 16.8ms(개발 PC). 조작 중인 요소만 별도 레이어로 그린다.
- 실제 앱 경로의 20장×사진 3장(합성 사진 60장, 저장 45.6MB, 개발 PC): 사진 1장 입력 약 164ms, 장 전환 약 65ms. 브라우저 전체 메모리는 시작 367MB, 20장을 넘긴 뒤 524MB, 출력 후 692MB. 편집용 PPT 45.7MB·5초, 모양 그대로 PPT 7.8MB·2.9초, PDF 8.2MB·1.8초.
- 라이브러리 그림·사진·배경을 함께 쓴 작품의 원본 저장 → 그림 파일을 막은 새 프로필에서 열기 → 내용 일치, PowerPoint 2종 열기와 PDF 렌더를 눈으로 비교했다.
- 실제 PowerPoint(COM)로 편집용·모양 그대로 PPT를 열어 4장 모두 렌더하고 글씨 줄을 읽었다. 사진·획·글씨 순서가 유지됨을 눈으로 확인했다(`scripts/phase3-montage.py`, `npm test`가 지우므로 PowerPoint 스크립트 뒤에 다시 만든다).
- PPT 세로 위치: 줄 간격 1~2, 글씨 크기 24·36·64px에서 측정해 줄 간격에 따라 보정한다. 보정 후 결과는 PHASE2_RESULTS.md §4에 있다.
- 시험 주의: `tests/contracts/autosave.spec.ts`는 실제 타이머를 5~30ms 여유로 쓴다. 느린 PC에서 이 파일만 실패하면 회귀로 단정하지 말고 먼저 다시 돌려 본다.
- 고친 결함(2026-11-06, 사용자 발견): 슬라이드에서 지운 사진을 작품을 다시 연 뒤 넣은 사진에서 넣으면 빈 칸이 되고 `저장 실패`가 났다. 문서의 자료 목록에는 남겨 두면서 사진 자료는 슬라이드가 쓰는 것만 저장하고, 지운 사진은 정리 때 삭제했기 때문이다. 미리보기는 메모리에 남아 있어 멀쩡해 보였다. 이제 자료 목록의 사진을 모두 보관한다. 이전 버전에서 이미 자료를 잃은 사진은 복구할 수 없어 목록에서 빠지며 다시 올려야 한다. 사진을 읽지 못해도 캔버스는 나머지 내용을 계속 그린다. 시험은 `tests/e2e/drag.spec.ts`다. 수정 후 사용자가 실제 브라우저에서 사진이 보이는 것을 확인했다.
- 고친 결함(2026-11-06, 사용자 발견): 공백·영문 없이 드문 한글로만 된 글씨(`튼튼` 등)를 선택해 글꼴을 바꾸면 문서는 바뀌는데 캔버스가 그대로이고 출력도 실패했다. 글꼴 확인을 글 내용이 아니라 고정 글자 `가`로 해서, 그 글자 묶음을 받지 않은 글꼴을 실패로 판단했기 때문이다. 앱 화면이 기본 글씨로 `가`를 늘 받아 두어 글꼴이 하나일 때는 드러나지 않았다. 이제 실제 글 내용으로 확인한다. 글꼴을 정말 받지 못하면 안내하고 화면은 대체 글꼴로 지금 문서를 보여 주며, 출력은 멈춘다. 실패한 글꼴은 새로고침해야 다시 받는다. 시험은 `tests/e2e/text.spec.ts`의 글꼴 항목이다. 수정 후 사용자가 실제 브라우저에서 글꼴이 바로 바뀌는 것을 확인했다.
- Phase 10 확인: `npm run test:release` 12건. 결과와 큰 문서 측정은 통합 시험 보고서에 있다.
- 측정 범위 밖: 프로젝터·터치 기기의 발표, 한쇼·Google Slides·PowerPoint 웹, 출력 중 메모리, 실제 저장 공간 부족, Chromium 외 브라우저의 잠금, 물리 터치, iPad, RAM 8GB 기기, 실제 사진이 많은 큰 문서, 실제 Canva 편집기와의 일치.
- 편의 결정: 발표는 지금 보던 장에서 시작하고, 마지막 장에서 더 넘기면 끝나지 않고 멈춘다. 화면 왼쪽 4분의 1을 누르면 앞 장, 나머지는 다음 장이다. 조작 줄은 3초 뒤 숨는다. 파일을 만드는 동안에는 발표를 시작할 수 없고, 작품을 떠나면 만들던 파일은 취소된다. 저장 작품이 있으면 작품 목록에서 시작하고, 없으면 새 작품으로 바로 들어간다. 새로고침하면 같은 탭에서 보던 작품으로 돌아온다. 손대지 않은 새 작품은 저장하지 않아 목록에 남지 않는다. 다른 작품으로 넘어갈 때 묻지 않고 자동 저장하며, 실패할 때만 묻는다. 잠금 미지원 브라우저는 읽기 전용으로 연다. 고아 사진은 작품 목록에 들어올 때 다른 탭이 없으면 정리한다. Esc와 다른 곳 누르기는 입력을 확정한다(입력 취소는 입력 중 Ctrl+Z). Esc로 끝내면 글씨가 선택된 채로 남고, 빈 곳을 눌러 끝내면 선택도 풀린다. 입력 중 되돌리기 버튼은 입력을 확정한 뒤 되돌린다. 창 폭 1200px 이상이면 디자인 패널을 연 채로 시작하고, 그보다 좁으면 닫고 시작한다. 불투명한 입력 사진은 JPEG(품질 0.9), 투명한 사진만 PNG로 저장한다. 안내 문구는 슬라이드를 덮지 않도록 설정 줄 오른쪽에 둔다. Backspace도 Delete와 같이 선택 요소를 지운다(되돌릴 수 있음). 슬라이드 끌어 옮기기는 마우스만 지원하고 터치는 장 메뉴를 쓴다. 패널 그림 끌어 넣기도 터치에서는 시작하지 않는다. 터치는 패널 스크롤에 쓰므로 누르기로 넣는다.
- 알려진 제약: 지운 사진도 작품의 사진 용량 한도(200MiB, 1000개)에 계속 포함된다. 넣은 사진 목록에서 지우는 기능은 없다. 번들 크기 경고가 남아 있다(첫 스크립트 756KB, 출력 도구는 내려받을 때 불러온다). 배포 결과 24MB. `.woff`는 빌드 때 지우고 `.woff2`만 남기며, 글꼴은 글자 묶음 단위로 필요할 때만 받는다. `.canvacraft`를 막는 호스트에서는 템플릿이 열리지 않는다([RELEASE.md](RELEASE.md)). 잘린 JPEG는 브라우저가 앞부분만 디코딩해 들어올 수 있다. 도형 색 변형 파일은 manifest에 해시가 없어 형식·크기·라이선스만 확인한다.

## 5. 다음 AI에게

- 화면 기준은 UI_REFERENCE.md다. 차트는 구현하지 않는다. 내장 그림의 형식은 [ASSET_LIBRARY_READY.md](ASSET_LIBRARY_READY.md)에 있다.
- Phase 4~8은 매번 `tests/e2e/flow.spec.ts`가 계속 통과하는지 확인한다. 새 필드가 생기면 `scripts/make-fixture.mjs`와 샘플 문서를 먼저 고친다.
- Konva 끌기·Transformer·hit 그래프를 쓰지 않는다. 포인터는 `SelectionLayer`가 받아 논리 좌표로 바꾸고, 조작 중 값은 `preview`로만 보관하다가 손을 뗄 때 명령을 한 번 보낸다. Konva scale을 쓰지 않으므로 값이 누적되지 않는다.
- 글씨 입력은 `src/editor/TextEditor.tsx`다. 값을 React로 되써넣지 않는다. 입력을 끝내는 일은 `flushEdit`로만 하며, 조합 중이면 compositionend를 기다린다. 문서를 바꾸는 다른 조작도 먼저 `flushEdit`를 거친다.
- 사용자 사진은 `importAsset`으로 항상 다시 만들고, 내장 그림은 원본 바이트를 유지한다. 내장 그림을 재인코딩하면 PNG의 라이선스 정보가 사라지므로 두 경로를 합치지 않는다.
- 글꼴을 더 넣을 때는 `src/domain/limits.ts`(FONT_IDS, BOLD_FONT_IDS), `src/rendering/text/fonts.ts`(등록표), `src/app/main.tsx`(CSS import), `public/licenses`, `docs/asset-licenses.md`를 함께 고친다. 대응값은 `tests/phase2/fontfit.spec.ts`로 잰다(`-g "한글 폭"`, `-g 측정용` → `pwsh -NoProfile -File scripts/phase2-powerpoint.ps1 -Dir artifacts/fontfit` → `-g 위치`).
- 발표는 `renderSlide`로 스냅샷을 그리며 문서를 바꾸지 않는다. 고해상도 캔버스는 지금 장과 앞뒤 장만 유지한다. 키 입력은 `Presenter`가 창 캡처 단계에서 끊어 편집 단축키가 닿지 않게 한다.
- 저장은 `createAutosave`가 작품당 한 번에 하나만 돌린다. 작품 전환·원본 열기는 `afterSaved`를 거친다. 저장 잠금 순서는 catalog → 작품이고, 공유 잠금을 쥔 채 배타 잠금을 기다리지 않는다. 고아 사진 삭제는 배타 catalog 안에서만 한다.
- 사용자에게 Phase 2 전체 완료라고 보고하지 않는다. 문서 분담이나 병렬 작업을 시작하지 않는다.
- `public/backgrounds-illustrated`(이미지 생성 도구로 만든 배경, 시험 1장)는 GPT가 작업 중으로 보이며 인계 문서가 없어 앱에 연결하지 않았다. 배포 결과에서는 `scripts/prune-dist.mjs`가 뺀다. 연결할 때 그 줄을 지운다.
- `dist/index.html`의 보안 정책은 `scripts/prune-dist.mjs`가 넣는다. 외부 자원을 새로 쓰거나 글꼴을 `data:`로 넣으면 배포본에서만 막힌다. 그래서 `npm run test:release`가 개발 서버 시험과 별도로 필요하다.
- 시험 시 Playwright로 큰 파일을 숫자 배열로 넘기지 않는다. 약 10MB 파일 두 개에서 실행 컨텍스트가 끊겼고 base64로 바꾸자 통과했다.
