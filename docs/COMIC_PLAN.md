## 3분 요약

**무엇을 만드는가.** 어린이가 **칸**을 하나씩 그리고, 말풍선을 넣어 대사를 쓰고, **만화 보기**로 칸들이 한 쪽에 모인 모습을 확인한 뒤, 인쇄할 수 있는 **만화책 PDF**나 **그림(PNG)**으로 내려받는 편집기다. 로그인·서버·업로드 없이 브라우저 안에서 끝낸다.

**어디에 붙이는가.** 시작 화면에 넷째 타일 **만화 만들기**를 추가한다. 슬라이드·영상·애니메이션과 나란히 놓이는 별도 프로그램이다.

**핵심 생각 두 가지.**

- **칸 하나가 장 하나다.** 만화의 칸을 슬라이드의 장(`Slide`, 1280×720)으로 삼는다. 아이는 칸 하나를 지금의 편집 화면에서 크게 그린다. 여러 칸을 한 쪽에 나란히 놓는 일(쪽 구성)은 보기·내려받기 때 프로그램이 한다. 애니메이션에서 "장 = 프레임"으로 삼은 것과 같은 방식이라 장 형태·편집 명령·`renderSlide`·편집 화면을 고치지 않고 쓴다.
- **말풍선은 그림 하나와 글씨 하나의 짝이다.** 말풍선 모양 그림(사진 요소)과 그 안의 대사(글씨 요소)를 한 번에 넣고, 만화 문서가 "이 그림과 이 글씨는 짝"이라고 기억한다. 말풍선을 옮기거나 지우거나 복제하면 글씨가 함께 움직인다. 새 요소 종류를 만들지 않으므로 슬라이드의 문서 형태는 바뀌지 않는다(§7, §10 결정 3).

**구조.** 애니메이션과 같다.

- **분리하는 것.** 만화 작품은 자기 문서 종류(`ComicProject`), 자기 저장소(IndexedDB `canvacraft-comic`), 자기 원본 파일(`.canvacomic`), 자기 작품 목록을 가진다.
- **재사용하는 것.** 장 형태, 편집 명령 18개, `renderSlide`, 그리기·글씨·사진·선택 부품, 편집 화면(`Editor`와 애니메이션 때 연 선택 인자).
- **슬라이드 쪽에서 바뀌는 것.** 선택 인자 몇 개와 넷째 타일뿐이다(§2 표). 슬라이드의 문서 형태·검사·명령·저장 코드·원본 파일 형식은 바뀌지 않는다. 슬라이드·영상 시험 파일을 고치지 않고 통과하는 것이 매 단계의 조건이다.

**이미 되는 것과 새로 생기는 것.** 지금 슬라이드 편집기로도 한 칸짜리 그림에 말풍선 그림(요소의 '둥근 말풍선'·'네모 말풍선')과 글씨를 따로 올릴 수는 있다. 만화 만들기가 더하는 것은 네 가지다. ① 칸들을 한 쪽에 모아 보여 주고 인쇄용으로 내보내는 쪽 구성, ② 한 번에 넣고 함께 움직이는 말풍선, ③ 만화용 그림 묶음(말풍선 9종, 효과 그림 12종)과 효과 글씨, ④ 만화 작품만 모인 목록.

**일정.** 9~12 작업일(§8 단계 합계, 추정). 2026-11-12 대화에서 말한 6~9일보다 늘었다. 늘어난 까닭은 말풍선 짝을 지키는 규칙(옮기기·크기 바꾸기·지우기·복제·칸 복제마다 짝을 맞춘다)과 만화용 그림을 직접 만드는 일을 그때 세지 않았기 때문이다.

**가장 큰 위험.** ① 말풍선 짝 규칙이 편집 명령 여덟 가지에 걸쳐 있어 빠뜨린 경우가 생기기 쉽다(§11). 계약 시험으로 명령마다 확인한다. ② 칸의 비율이 16:9로 고정이다. 세로로 긴 칸이나 크기가 다른 칸은 만들 수 없다. ③ 인쇄 품질과 A4 여백은 실제 프린터로 봐야 안다(사용자 확인 항목).

**사용자가 정할 것.** §10의 14개. 큰 결정은 셋이다. 결정 2(칸 하나 = 장 하나), 결정 3(말풍선 방식), 결정 4(저장·목록 코드를 애니메이션과 함께 쓸지). 나머지는 기본값이 있다.

## 1. 목표와 범위

### 어린이가 하는 일 (대표 흐름)

1. 시작 화면에서 **만화 만들기**를 누른다. 만화 작품 목록에서 **새 작품**을 누른다.
2. 첫 칸에 배경을 고르고 캐릭터·그리기·사진으로 장면을 만든다(슬라이드와 같은 도구).
3. 만화 패널에서 **말풍선**을 고른다. 칸 가운데에 말풍선과 글씨 칸이 생기고 바로 대사를 쓴다. 말풍선을 끌어 캐릭터 옆으로 옮긴다.
4. 효과 그림(집중선, 반짝, 땀방울)이나 효과 글씨(쾅!, 두근두근)를 올린다.
5. 하단 칸 목록의 **+** 타일("다음 칸 만들기")로 다음 칸을 만든다. 2~4를 반복한다.
6. 상단 **만화 보기**를 누르면 칸들이 한 쪽에 모인 모습이 보이고, 화살표로 쪽을 넘긴다.
7. 만화 패널에서 **칸 배치**(한 쪽에 3칸·4칸·8칸)를 바꿔 본다.
8. 공유 → 내려받기에서 **만화책 (PDF)**을 골라 내려받아 인쇄하거나, **그림 (PNG)**으로 지금 쪽을 내려받는다.

### 넣지 않는 것 (후속 범위)

크기나 비율이 다른 칸, 칸 테두리 모양 바꾸기, 꼬리를 끌어 방향을 바꾸는 말풍선, 글씨 길이에 맞춰 저절로 커지는 말풍선, 세로쓰기, 오른쪽에서 왼쪽으로 읽는 순서, 지은이 이름 칸, 표지 쪽, 웹툰처럼 세로로 긴 한 장 출력, 여러 쪽을 한 번에 그림으로 내려받기, 고칠 수 있는 PowerPoint 출력, 슬라이드 작품을 만화로 가져오기, 만화용 그림을 슬라이드·애니메이션의 요소 패널에 보이기(결정 14).

### 만화 문서가 슬라이드 코드에 그대로 들어가는 이유

애니메이션과 같은 방법이다. `ComicProject`는 슬라이드 `Project`의 필드 10개를 같은 이름·같은 형태로 가지고 거기에 `kind`, `layout`, `bubbles`를 더한다. 필드가 더 많은 값은 필드가 적은 타입 자리에 넘길 수 있으므로 `renderSlide`·`SlideList`·`SlideCanvas`·`Editor`가 수정 없이 동작한다. 이 방법은 애니메이션에서 `tsc`와 시험 550개로 이미 확인됐다([animation-contracts.md](animation-contracts.md) §9 구현 기록 A4).

검사도 같다. `validateComicProject`는 슬라이드와 같은 10개 필드를 슬라이드의 `validateProject`에 넘기고 나머지 3개만 직접 검사한다.

## 3. 시작 화면·작품 목록·편집 화면

### 시작 화면과 화면 이동

| 화면 | 내용 |
|---|---|
| 시작 화면 | 타일 4개: 슬라이드(보라), 영상(주황), 애니메이션(초록), **만화 만들기(파랑)**. 타일 4개가 좁은 창에서도 화면 안에 들어오는지 K4에서 확인한다(지금 배포본 시험이 타일 3개의 위치를 본다). 최근 작품은 네 저장소의 요약을 각각 읽어 섞는다 |

| 화면 이동 | `App.tsx`의 `Screen`에 `{ kind: 'comic', resumeId }`를 더하고 `ComicApp`을 `lazy`로 불러온다. 만화를 쓰지 않는 아이의 첫 로딩 크기는 늘지 않는다 |
| 새로고침 복원 | `currentProject.ts`의 기억 값 종류에 `'comic'`을 더한다. 앞 버전이 이 값을 읽으면 `null`을 돌려주고 시작 화면으로 간다(애니메이션 때와 같은 동작) |

### 편집 화면: `Editor`에 넘기는 값

애니메이션 때 연 선택 인자(`EditorVariant`)를 그대로 쓴다. 표의 "새로 여는 지점"만 슬라이드 쪽 파일이 바뀐다.

| 지점 | 만화가 넘기는 값 | 인자 상태 |
|---|---|---|
| 저장·원본 파일 | `saveComicProject`, `serializeComic`·`deserializeComic`, 확장자 `canvacomic` | 이미 있음 |
| 여섯째 도구 | 만화 + `ComicPanel` | 이미 있음(`tool`) |
| + 타일 | 맨 뒤에 빈 칸(슬라이드 기본 동작), 이름 "다음 칸 만들기" | 이미 있음(`slideList.addLabel`) |
| 칸 목록 배지 | 쪽이 바뀌는 첫 칸에 "2쪽" | 이미 있음(`slideList.badge`) |
| 발표 단추 | 만화 보기 + `ComicReader` | 이미 있음(`present`) |
| 내려받기 형식 추가 | 만화책 (PDF), 그림 (PNG) | 이미 있음(`exports`) |
| **기본 형식 숨기기** | PowerPoint 2종과 칸마다 한 쪽인 PDF를 내려받기 창에서 뺀다. "PDF"가 두 개 보이면 아이가 헷갈린다 | **새로 여는 지점.** `EditorVariant`와 `TopBar`에 선택 인자 하나 |
| **그림 등록** | 만화 패널이 말풍선·효과 그림을 받아 작품의 사진 목록에 등록하고 명령을 보낸다 | **새로 여는 지점.** `EditorApi`에 함수 하나(지금 `Editor` 안의 `addLibraryItem`이 하는 일을 패널이 부를 수 있게) |
| **끄는 동안 함께 보일 요소** | 말풍선을 끄는 동안 짝 글씨도 같은 만큼 옮겨 보인다 | **새로 여는 지점(선택 사항).** 지금 `Editor`는 끄는 요소 하나만 임시로 그린다. 열지 않으면 글씨는 손을 뗄 때 따라온다. K2에서 정한다 |

양파 껍질(`Underlay`)과 확대/축소 옆 단추(`zoomExtra`)는 쓰지 않는다.

### 화면 배치

| 영역 | 만화에서의 내용 |
|---|---|
| 상단 바 | 같다. 발표 자리에 **만화 보기**. 내려받기 창에는 **만화책 (PDF)**("칸들을 종이 한 장에 모아요. 인쇄할 수 있어요"), **그림 (PNG)**("지금 쪽을 그림 한 장으로 받아요") |
| 왼쪽 도구 모음 | 배경 / 요소 / 텍스트 / 업로드 / 그리기 / **만화** |
| 만화 패널 | 말풍선 카드(모양 5종, 꼬리 왼쪽·오른쪽), 효과 그림 카드 12종, 효과 글씨 단추 6종, 칸 배치 단추 3개, 지금 크기("8칸 · 2쪽"), 처음이면 안내 |
| 중앙 작업 공간 | 지금 칸 하나. 슬라이드와 같다 |
| 하단 칸 목록 | 카드마다 쪽이 바뀌는 자리에 "n쪽" 배지. + 타일은 "다음 칸 만들기" |
| 만화 보기 | 작업 공간을 덮는 층 위에 쪽 그림 한 장, 좌우 화살표, 쪽 번호 n / N, 닫기. 칸을 누르면 닫히면서 그 칸으로 간다 |

어린이용 단순화 규칙: 숫자 입력 칸을 두지 않는다. 칸 배치는 단추 3개, 말풍선 꼬리는 그림 2개 중 고르기다.

## 4. 데이터 구조와 명령

원칙은 다른 편집기와 같다. 문서는 변경 불가능한 값이고, 바꾸는 곳은 `comicStore.ts`의 dispatch·undo·redo 하나다. 만화 보기에서 보고 있는 쪽, 쪽 그림 캐시는 문서가 아니다.

### 저장 객체 (초안, K1에서 계약으로 확정)

| 객체 | 필드와 의미 |
|---|---|
| ComicProject | schemaVersion=1, **kind='comic'**, id, title, revision, createdAt, updatedAt, width=1280, height=720, **layout**, **bubbles**, slides, assetManifest. 굵은 것 외에는 슬라이드 `Project`와 이름·형태·검사가 같다 |
| layout | 칸 배치. `'rows3'`(세로 A4에 3칸)·`'grid4'`(가로 A4에 2×2)·`'grid8'`(세로 A4에 2×4) 중 하나. 새 작품은 `'grid4'` |
| bubbles | 말풍선 짝 목록. `{ "<말풍선 그림 요소 id>": "<글씨 요소 id>" }` 꼴의 객체다. 키는 사진 요소, 값은 글씨 요소여야 하고 둘은 같은 칸에 있어야 한다. 글씨 하나는 말풍선 하나에만 짝이 된다. `Slide`와 요소 타입에 필드를 더하지 않으려고 문서 쪽에 둔다(애니메이션의 `holds`와 같은 방식) |
| slides, assetManifest | 슬라이드와 같은 `Slide[]`·`Asset[]` |
| ComicSummary | projectId, kind='comic', title, updatedAt, revision, panelCount(칸 수), pageCount(쪽 수), thumbnailRevision, thumbnail(첫 칸 320×180 JPEG) |
| 되돌리기가 복원하는 내용 | title, slides, assetManifest, layout, bubbles |

쪽 수는 `⌈칸 수 ÷ 한 쪽의 칸 수⌉`다. 마지막 쪽의 남는 자리는 비워 둔다. 읽는 순서는 왼쪽에서 오른쪽, 위에서 아래다.

### 명령

| 명령 | 입력 | 실패 조건 | 취소 단위 |
|---|---|---|---|
| 슬라이드 명령 18개 | contracts.md §4와 같다 | 같다 | 같다. 짝이 함께 바뀐 것까지 한 번에 돌아간다 |
| setComicLayout | layout | 허용값 아님(INVALID_VALUE) | 고르기 1회 |
| addBubble | slideId, 말풍선 그림(assetId·자리·크기·`asset`), 글씨(자리·너비·글꼴·크기·색·정렬) | 슬라이드의 `addImage`·`addText`가 실패하는 조건과 같다(칸 없음, 개수 상한, 사진 누락) | 말풍선 1개(그림과 글씨가 한 번에 생기고 한 번에 사라진다) |

`comicApply.ts`는 슬라이드 명령을 받으면 문서에서 `title`·`slides`·`assetManifest`만 꺼내 슬라이드의 `applyCommand`에 넘기고, 결과를 문서에 다시 합친 뒤 아래 규칙으로 짝을 맞춘다. `history.ts`의 기록 하나가 바꾸기 전과 후의 내용 전체를 잡으므로, 짝을 맞추느라 요소 둘이 바뀌어도 되돌리기는 한 번이다.

| 슬라이드 명령 | 짝 맞추기 |
|---|---|
| `moveElement`(말풍선 그림) | 짝 글씨를 같은 거리만큼 옮긴다. 글씨가 좌표 범위를 벗어나면 범위 안으로 당긴다 |
| `moveElement`(짝 글씨) | 글씨만 옮긴다. 말풍선 안에서 글씨 자리를 고칠 수 있게 한다 |
| `resizeImage`(말풍선 그림) | 짝 글씨의 자리와 너비를 같은 비율로 바꾼다. 글씨 크기는 그대로 둔다 |
| `deleteElement`(말풍선 그림) | 짝 글씨도 지운다 |
| `deleteElement`(짝 글씨) | 짝만 푼다. 빈 말풍선 그림이 남는다 |
| `duplicateElement`(말풍선 그림) | 글씨도 복제하고 복제본끼리 짝을 짓는다 |
| `reorderElement`(말풍선 그림) | 짝 글씨를 말풍선 바로 위 순서로 옮긴다(글씨가 말풍선 뒤로 숨지 않게) |
| `duplicateSlide` | 복제된 칸의 요소는 id가 새로 생긴다. 요소 순서가 같으므로 순서로 맞춰 새 짝을 만든다 |
| `deleteSlide`, `clearSlide` | 사라진 요소의 짝을 뺀다 |
| 되돌리기·다시 하기 | `bubbles`가 내용에 들어 있어 따로 처리하지 않는다 |

## 5. 초기 상한 (K1 계약에서 확정)

슬라이드 상한(`domain/limits.ts`)을 그대로 쓴다. 칸 100개(4칸 배치면 25쪽), 칸마다 요소 1,000개, 사진 합계 200MB. 말풍선은 사진 요소 하나와 글씨 요소 하나로 세고 따로 상한을 두지 않는다. 만화 그림 묶음의 PNG는 한 변 512px 안팎으로 만들어 말풍선 하나가 작품 크기를 수십 KB만 늘리게 한다(같은 그림은 `assetManifest`에 한 번만 들어간다).

## 7. 말풍선·쪽 구성·내보내기 기술

### 말풍선

- **넣기.** 만화 패널에서 모양을 누르면 만화 그림 묶음의 PNG를 받아(해시 확인, 슬라이드의 그림 묶음과 같은 절차) 칸 가운데에 사진 요소로 넣고, 그 안쪽 영역에 가운데 정렬 글씨 요소를 넣고, 바로 글씨 입력 상태로 들어간다. 명령은 `addBubble` 하나다.
- **안쪽 영역.** 그림마다 글씨가 들어갈 네모(왼쪽·위·너비·높이의 비율)를 `public/comic/manifest.json`에 적는다. 꼬리가 있는 아랫부분을 피하기 위해서다.
- **글씨가 길 때.** 말풍선은 저절로 커지지 않는다. 글씨가 넘치면 아이가 말풍선 손잡이로 키우거나 글씨 크기를 줄인다. 사진 요소는 원본 비율을 지켜야 하므로(`validate.ts` 71행) 말풍선을 가로로만 늘릴 수는 없다. 그래서 같은 모양에 넓은 것과 보통 것을 함께 둘지를 K2에서 본다.
- **꼬리 방향.** 그림을 뒤집는 필드가 사진 요소에 없으므로 왼쪽 꼬리·오른쪽 꼬리 그림을 따로 둔다.
- **끄는 동안.** 지금 편집 화면은 끄는 요소 하나만 임시 위치에 그린다(`Editor`의 `preview`가 요소 하나다). 선택 인자를 열지 않으면 말풍선을 끄는 동안 글씨는 제자리에 있다가 손을 뗄 때 따라온다. K2에서 실제로 써 보고 거슬리면 `SlideCanvas`·`Editor`에 "함께 보일 요소" 선택 인자를 연다.
- **출력.** 말풍선은 보통의 사진 요소와 글씨 요소이므로 `renderSlide`가 그대로 그린다. 쪽 구성과 PDF·PNG에 따로 할 일이 없다.

### 쪽 구성

칸 그림은 `renderSlide(slide, resolve, 1)`(1280×720)로 만든다. 쪽 조립 함수 하나(`composePage`)가 흰 종이 위에 칸 그림을 놓고 검은 테두리를 긋고 첫 쪽의 제목과 쪽 번호를 쓴다. 만화 보기·PNG·PDF가 모두 이 함수의 결과를 쓰므로 화면과 인쇄물이 같다.

| 배치 | 종이 | 칸 크기(어림) | 칸 그림의 인쇄 해상도(어림) |
|---|---|---|---|
| `rows3` | 세로 A4 | 151 × 85mm | 약 215dpi |
| `grid4` | 가로 A4 | 136 × 77mm | 약 238dpi |
| `grid8` | 세로 A4 | 93 × 52mm | 약 350dpi |

수치는 여백 10mm, 제목 줄 14mm, 칸 사이 4mm로 계산한 추정이다. 정확한 값은 K1 계약에 포인트 단위로 적고 K2의 인쇄 시험으로 고친다. 제목은 작품 제목(`title`)을 지금 있는 글꼴로 그린다.

### 내보내기

| 형식 | 방법 |
|---|---|
| 만화책 (PDF) | 쪽마다 조립한 그림을 JPEG(품질 0.88, 슬라이드 PDF와 같은 값)로 A4 쪽에 넣는다. `pdf-lib`은 슬라이드 PDF가 이미 쓴다. 그림의 라이선스 고지는 슬라이드 PDF와 같이 첨부 파일로 넣는다. 100칸·4칸 배치면 25쪽이다 |
| 그림 (PNG) | 지금 칸이 들어 있는 쪽 하나를 PNG로 내려받는다 |
| 내보내는 동안의 편집 | 시작할 때의 문서 값(스냅숏)으로 만든다. 슬라이드·애니메이션과 같은 규칙이다 |

Worker·인코더·OPFS를 쓰지 않는다. 애니메이션의 MP4보다 단순하다.

### 실행 파일·정적 서버·CSP

새 외부 요청이 없다. `public/comic`의 파일은 같은 출처에서 받는다. CSP를 바꾸지 않는다.

## 8. 단계별 계획

한 AI가 순서대로 진행하고 PROGRESS.md에 인계한다. **모든 단계의 공통 조건: `npm test` 전체가 통과하고, 슬라이드·영상 시험 파일을 고치지 않는다.** 애니메이션 시험 파일도 고치지 않는다(예외: 배포본 시험의 타일 개수 확인은 넷째 타일에 맞춰 고친다).

### K1. 계약 확정 (1일)

- 작업: 새 문서 `docs/comic-contracts.md`. 문서 필드·명령 20개·짝 맞추기 규칙·검사 순서·상한·저장소·잠금·`.canvacomic`·쪽 크기와 칸 자리(포인트 단위)·만화 그림 묶음 manifest·`Editor`에 넘기는 값. 다른 계약과 같은 규칙은 "슬라이드 계약 §n과 같다"로만 적는다.
- 완료 기준: §1의 기능이 모두 필드·명령·화면 조작·출력 규칙에 연결된 대조표가 있고, §10 결정이 확정값으로 적혀 있다.

### K2. 먼저 확인할 것 (1일): 이 결과로 범위를 다시 정한다

- 작업: 제품 코드가 아닌 시험 페이지에서 본다.
  - 쪽 조립: 세 배치로 쪽 그림과 PDF를 만들어 화면에서 본다. 100칸 작품의 PDF 만드는 시간과 파일 크기.
  - 인쇄: 만든 PDF를 사용자가 실제 프린터로 한 장 뽑아 여백과 선명도를 본다(못 하면 미확인으로 기록).
  - 말풍선: 말풍선 그림 2~3개를 임시로 만들어 슬라이드 편집기에 사진으로 넣고, 글씨를 올려 크기 바꾸기·글씨 넘침을 써 본다. 넓은 모양이 따로 필요한지 정한다.

- `src/domain/validate.ts` 71행: 사진 요소의 가로세로 비율이 원본과 0.1% 넘게 다르면 거부한다(`LIMITS.imageAspectTolerance`).
- `src/commands/apply.ts` 11~29행: 명령은 18개이고 여러 요소를 한 번에 바꾸는 명령은 없다. `addSlide`는 `afterSlideId`를 받는다.
- `src/state/history.ts`: 기록 하나가 `before`·`after` 내용 전체를 잡는다. 명령 적용 함수가 요소 둘을 바꿔도 기록은 하나다.
- `public/library/manifest.json`: 그림 120개. 말풍선은 `shape-speech-round`(둥근 말풍선)·`shape-speech-square`(네모 말풍선) 두 개이고 512×408 그림이다. 글씨와 묶이지 않는다.
- `src/app/Editor.tsx`: 선택은 요소 하나다(여러 개 선택 없음). 끄는 동안의 임시 위치 `preview`는 요소 하나다(103행). `addLibraryItem`(318행)이 그림을 받아 `placeImage`로 넣는다. `EditorApi`(69행)는 `perform`·`readOnly`·`slide`·`setStatus` 네 개다.
- `src/editor/SelectionLayer.tsx`: 끄는 동안에는 `onPreview`로 임시 위치만 알리고 손을 뗄 때 명령을 한 번 보낸다.
- `src/app/TopBar.tsx` 6~11행: 기본 내려받기 형식은 `pptx`·`pdf`·`image`(모양 그대로 PowerPoint)다. 그림 파일(PNG) 내려받기는 없다.
- `src/export/exportPdf.ts`: 장마다 `renderSlide` 결과를 JPEG(품질 0.88)로 `pdf-lib` 쪽에 넣는다. 라이선스 고지는 첨부 파일이다.
- `src/app/StartScreen.tsx` 41~44행: 타일 3개가 한 줄(`start-tiles`)에 있다.
- `src/animation/`: `animationDatabase.ts` 144줄, `animationFile.ts` 90줄, `AnimationApp.tsx` 72줄, `AnimationHome.tsx` 109줄. 데이터베이스 이름과 검사 함수가 파일 안에 상수로 들어 있다.
- `src/assets/library.ts`: `loadLibraryImage`가 그림을 받아 해시를 확인하고 `{ asset, blob }`을 돌려준다. `LibraryItem` 형태를 만화 그림 묶음이 그대로 쓸 수 있다.
