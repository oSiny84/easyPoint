# 배포 패키지와 되돌리는 절차

공개 배포는 별도 작업이다. 이 문서의 절차로 패키지를 만들었다고 배포가 끝난 것이 아니다. 웹 호스트에는 아직 배포하지 않았다. 실행 파일은 사용자 요청으로 2026-11-06 GitHub에 `v0.0.1`(프리릴리스)과 `v0.0.2`(릴리스, 그림 배경 16종 추가)로, 2026-11-10 `v0.0.3`(프리릴리스, 영상 편집기 포함, 브랜치 `claude/kids-video-editor-planning-29695d`에서 만듦)과 `v0.0.4`(프리릴리스, 조각 빠르기·길이 한도 설정·긴 작품 타임라인, 같은 브랜치), `v0.0.5`(프리릴리스, 빠른 조각 미리보기 깜빡임 수정·스페이스 재생, 같은 브랜치)로 올렸고, 저장소가 공개 상태라 누구나 받을 수 있다.

## 공개하기 전에 정할 것

| 항목 | 판단 | 내용 |
|---|---|---|
| 이름과 화면 권리 | **확인 후 결정** | Canva와 비슷한 배치와 CanvaCraft라는 이름을 공개해도 되는지 검토하지 않았다. 저장소 이름은 easyPoint다. 소스와 실행 파일은 이 검토 전에 공개됐다 |
| 터치 기기·실제 호스트·8GB 기기 | **확인 후 결정** | [통합 시험 보고서](INTEGRATION_REPORT_2026-11-06.md)의 미확인 항목 |
| 어린이 사용성 관찰 | **확인 후 결정** | 미실시 |

## 집·교실 PC용 실행 파일

웹 호스트 없이 PC 한 대에서 쓸 때는 실행 파일 하나로 나눠 준다.

```bash
npm run exe
```

`artifacts/release/CanvaCraft.exe`(v0.0.5 약 64MB: 그림 배경 16장 약 39MB, 배경음악·효과음 약 8MB)가 생긴다. 앱 파일을 품고 있고, 실행하면 `http://127.0.0.1:47831/`을 기본 브라우저로 연다. 이 컴퓨터 안의 연결만 받으므로 방화벽 창이 뜨지 않고 사진이 밖으로 나가지 않는다. Windows 10·11에 기본으로 있는 .NET Framework 4로 돌아가며, 빌드에도 Windows 기본 C# 컴파일러만 쓴다.

| 항목 | 내용 |
|---|---|
| 연결 번호 47831 | **바꾸지 않는다.** 브라우저는 주소별로 작품을 저장하므로 바꾸면 저장된 작품이 보이지 않는다 |
| 두 번 실행 | 둘째는 켜져 있는 쪽을 열고 바로 끝난다 |
| 끝내기 | 알림 영역 아이콘의 `끝내기`. 끝내도 작품은 브라우저에 남는다 |
| 새 버전 | 앞 버전을 끝내고 파일을 바꾼다. 앞 버전이 켜져 있으면 안내한다. 작품은 그대로다 |
| 서명 | 코드 서명을 하지 않았다. 인터넷으로 받으면 SmartScreen 경고가 나올 수 있다 |
| 시험 | `npm run test:exe`: 실행 파일로 배포본 시험 전체(영상 편집기 열기·가져오기·재생·MP4 내보내기 포함), 경로·Host 거부, 두 번 실행, 다시 켜도 작품 유지. 다른 PC와 알림 영역 아이콘은 사람 확인 항목이다 |
| 코드 라이선스 | 실행 파일에 Mediabunny 1.62.1(MPL-2.0)을 고치지 않고 넣는다. MPL-2.0은 실행 형태로 나눠 줄 때 원본 코드를 구할 곳을 알리게 하므로, 릴리스 안내에 저장소(https://github.com/Vanilagy/mediabunny)와 npm 판 이름을 적는다. 앱 화면 안의 고지는 아직 없다 |

실행 파일을 GitHub에 올릴 때:

```bash
gh release create v<버전> artifacts/release/CanvaCraft.exe --target <커밋된 브랜치> --prerelease --title "CanvaCraft <버전>" --notes-file <안내 파일>
```

되돌리려면 `gh release delete v<버전> --cleanup-tag`로 지운다. 이미 받은 사람의 파일까지 지울 수는 없다.

## 패키지 만들기

```bash
npm ci
npm test
npm run test:release
npm run package
```

`artifacts/release/canvacraft-web-<버전>-<커밋>.zip`과 같은 이름의 `.sha256`이 생긴다. 커밋하지 않은 변경이 있으면 이름에 `-dirty`가 붙으며, 그 파일은 배포하지 않는다.

## 호스트 조건

정적 파일만 내주면 된다. 서버 프로그램이나 데이터베이스는 필요 없고, 사진과 작품을 받는 서버도 없다.

| 조건 | 이유 |
|---|---|
| **HTTPS 필수** | 탭 잠금(Web Locks)이 보안 연결에서만 동작한다. 일반 http 주소에서는 브라우저가 이 기능을 주지 않아 모든 작품이 읽기 전용으로 열린다(127.0.0.1 제외. 기능을 끈 상태로 시험했고 실제 http 호스트에서는 시험하지 않았다). 파일을 더블클릭해 여는 방식도 지원하지 않는다 |
| 하위 경로 가능 | 상대 경로로 빌드한다. `http://127.0.0.1:4180/canvacraft/`에서 시험했다 |
| `.canvacraft` 파일을 그대로 내줌 | 템플릿 파일이다. 시험에서는 `application/octet-stream`으로 내줬다. 호스트가 알 수 없는 확장자를 막으면 템플릿이 열리지 않는다 |
| `index.html` 캐시 안 함, `assets/`는 오래 캐시 | `assets/`의 파일 이름에는 내용 해시가 들어 있다. `index.html`이 캐시되면 새 버전이 늦게 보인다 |
| 응답 헤더 `Content-Security-Policy: frame-ancestors 'none'` 권장 | 그 밖의 정책은 `index.html`의 meta에 들어 있지만 이 항목은 meta로 지정할 수 없다 |

## 올리기

1. `.sha256`으로 압축 파일을 확인한다.
2. 압축을 풀어 호스트의 대상 폴더에 올린다. 앞 버전의 압축 파일은 지우지 않고 보관한다.
3. 공개 주소에서 아래 확인을 한다.

## 올린 뒤 확인(약 5분)

1. 주소를 열어 빈 작품이 나오는지, 글씨가 Noto Sans KR로 보이는지 본다.
2. 슬라이드를 추가해 `저장됨`이 뜨는지, 새로고침해도 남는지 본다. `읽기 전용`이 뜨면 HTTPS가 아닌 것이다.
3. 템플릿 하나를 열어 본다.
4. PDF와 PowerPoint를 하나씩 내려받아 연다.
5. 발표를 시작하고 끝낸다.
6. 개발자 도구의 Network에서 다른 주소로 나가는 요청이 없는지, Console에 Content Security Policy 오류가 없는지 본다.

## 되돌리기

1. 보관한 앞 버전 압축 파일의 내용으로 대상 폴더를 바꾼다.
2. 위 확인을 다시 한다.

작품은 사용자 브라우저에 있으므로 앱 파일을 바꿔도 지워지지 않는다. 지금까지 저장소 구조(`canvacraft` 데이터베이스 버전 1)와 문서 형식(`schemaVersion` 1)을 올린 적이 없어 앞 버전으로 되돌려도 저장된 작품을 연다. 예외로, v0.0.4에서 조각 빠르기를 쓴 영상 작품은 v0.0.3에서 열리지 않는다(v0.0.3이 `Clip.speed` 필드를 모른다). **이 값을 올리는 버전을 배포한 뒤에는 앞 버전이 새 형식의 작품을 열지 못하므로, 그 버전부터는 되돌리기 계획을 따로 세운다.**

앱을 연 채로 새 버전이 배포되면 그 탭에서 파일 내려받기 도구를 불러오지 못할 수 있다. 앱이 새로고침을 안내한다.

## 배포본 시험의 범위

`npm run test:release`는 `dist`를 `http://127.0.0.1:4180/canvacraft/`에서 내주고 Chromium으로 시험한다. 실제 호스트, HTTPS, CDN은 시험하지 않는다.
