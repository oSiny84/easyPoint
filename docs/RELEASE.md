# 배포 패키지와 되돌리는 절차

공개 배포는 별도 작업이다. 이 문서의 절차로 패키지를 만들었다고 배포가 끝난 것이 아니다. 웹 호스트에는 아직 배포하지 않았다. Vercel에 올릴 설정(`vercel.json`)은 2026-11-12 준비했고 실제로 올려 보지는 않았다(§Vercel에 올리기). 실행 파일은 사용자 요청으로 2026-11-06 GitHub에 `v0.0.1`(프리릴리스)과 `v0.0.2`(릴리스, 그림 배경 16종 추가)로, 2026-11-10 `v0.0.3`(프리릴리스, 영상 편집기 포함, 브랜치 `claude/kids-video-editor-planning-29695d`에서 만듦)과 `v0.0.4`(프리릴리스, 조각 빠르기·길이 한도 설정·긴 작품 타임라인, 같은 브랜치), `v0.0.5`(프리릴리스, 빠른 조각 미리보기 깜빡임 수정·스페이스 재생, 같은 브랜치)로, 2026-11-12 `v0.0.6`(프리릴리스, 애니메이션·만화 편집기 추가, 브랜치 `claude/kids-program-features-205ebd`에서 v0.0.5를 합쳐 만듦)으로 올렸고, 저장소가 공개 상태라 누구나 받을 수 있다.

## 공개하기 전에 정할 것

| 항목 | 판단 | 내용 |
|---|---|---|
| 이름과 화면 권리 | **확인 후 결정** | Canva와 비슷한 배치를 공개해도 되는지 검토하지 않았다. 앱 이름은 Canva와 겹치지 않게 2026-11-12에 CanvaCraft에서 easyCraft로 바꿨다(v0.0.6까지의 실행 파일은 `CanvaCraft.exe`). GitHub 저장소 이름도 같은 날 easyPoint에서 easyCraft로 바꿨다(예전 주소는 GitHub이 넘겨준다). 소스와 실행 파일은 이 검토 전에 공개됐다 |

| 어린이 사용성 관찰 | **확인 후 결정** | 미실시 |

## 집·교실 PC용 실행 파일

웹 호스트 없이 PC 한 대에서 쓸 때는 실행 파일 하나로 나눠 준다.

```bash
npm run exe
```

`artifacts/release/easyCraft.exe`(v0.0.6은 `CanvaCraft.exe`, 약 64MB: 그림 배경 16장 약 39MB, 배경음악·효과음 약 8MB)가 생긴다. 앱 파일을 품고 있고, 실행하면 `http://127.0.0.1:47831/`을 기본 브라우저로 연다. 이 컴퓨터 안의 연결만 받으므로 방화벽 창이 뜨지 않고 사진이 밖으로 나가지 않는다. Windows 10·11에 기본으로 있는 .NET Framework 4로 돌아가며, 빌드에도 Windows 기본 C# 컴파일러만 쓴다.

| 항목 | 내용 |
|---|---|
| 연결 번호 47831 | **바꾸지 않는다.** 브라우저는 주소별로 작품을 저장하므로 바꾸면 저장된 작품이 보이지 않는다 |
| 두 번 실행 | 둘째는 켜져 있는 쪽을 열고 바로 끝난다 |
| 끝내기 | 알림 영역 아이콘의 `끝내기`. 끝내도 작품은 브라우저에 남는다 |
| 새 버전 | 앞 버전을 끝내고 파일을 바꾼다. 앞 버전이 켜져 있으면 안내한다. 작품은 그대로다 |
| 서명 | 코드 서명을 하지 않았다. 인터넷으로 받으면 SmartScreen 경고가 나올 수 있다 |
| 시험 | `npm run test:exe`: 실행 파일로 배포본 시험 전체(영상 편집기 열기·가져오기·재생·MP4 내보내기, 애니메이션 만들기·재생·MP4 내려받기, 만화 만들기·만화 보기·PDF·PNG 내려받기 포함), 경로·Host 거부, 두 번 실행, 다시 켜도 작품 유지. 다른 PC와 알림 영역 아이콘은 사람 확인 항목이다 |
| 코드 라이선스 | 실행 파일에 Mediabunny 1.62.1(MPL-2.0)을 고치지 않고 넣는다. MPL-2.0은 실행 형태로 나눠 줄 때 원본 코드를 구할 곳을 알리게 하므로, 릴리스 안내에 저장소(https://github.com/Vanilagy/mediabunny)와 npm 판 이름을 적는다. 앱 화면 안의 고지는 아직 없다 |

실행 파일을 GitHub에 올릴 때:

```bash
gh release create v<버전> artifacts/release/easyCraft.exe --target <커밋된 브랜치> --prerelease --title "easyCraft <버전>" --notes-file <안내 파일>
```

되돌리려면 `gh release delete v<버전> --cleanup-tag`로 지운다. 이미 받은 사람의 파일까지 지울 수는 없다.

## 패키지 만들기

```bash
npm ci
npm test
npm run test:release
npm run package
```

`artifacts/release/canvacraft-web-<버전>-<커밋>.zip`과 같은 이름의 `.sha256`이 생긴다. 커밋하지 않은 변경이 있으면 이름에 `-dirty`가 붙으며, 그 파일은 배포하지 않는다.

## 호스트 조건

정적 파일만 내주면 된다. 서버 프로그램이나 데이터베이스는 필요 없고, 사진과 작품을 받는 서버도 없다.

| 조건 | 이유 |
|---|---|
| **HTTPS 필수** | 탭 잠금(Web Locks)이 보안 연결에서만 동작한다. 일반 http 주소에서는 브라우저가 이 기능을 주지 않아 모든 작품이 읽기 전용으로 열린다(127.0.0.1 제외. 기능을 끈 상태로 시험했고 실제 http 호스트에서는 시험하지 않았다). 파일을 더블클릭해 여는 방식도 지원하지 않는다 |
| 하위 경로 가능 | 상대 경로로 빌드한다. `http://127.0.0.1:4180/canvacraft/`에서 시험했다 |
| `.canvacraft` 파일을 그대로 내줌 | 템플릿 파일이다. 시험에서는 `application/octet-stream`으로 내줬다. 호스트가 알 수 없는 확장자를 막으면 템플릿이 열리지 않는다 |
| `index.html` 캐시 안 함, `assets/`는 오래 캐시 | `assets/`의 파일 이름에는 내용 해시가 들어 있다. `index.html`이 캐시되면 새 버전이 늦게 보인다 |
| 응답 헤더 `Content-Security-Policy: frame-ancestors 'none'` 권장 | 그 밖의 정책은 `index.html`의 meta에 들어 있지만 이 항목은 meta로 지정할 수 없다 |

## Vercel에 올리기

Vercel은 GitHub 저장소를 연결하면 푸시할 때마다 직접 빌드해서 올린다. 그래서 위의 압축 파일은 쓰지 않는다. 호스트 조건은 저장소 루트의 `vercel.json`이 맞춘다. 2026-11-12에 설정만 준비했고 실제 Vercel 프로젝트는 만들지 않았다.

| 호스트 조건 | Vercel에서 |
|---|---|
| HTTPS | Vercel이 기본으로 준다 |
| 빌드 | `vercel.json`이 `npm ci`, `npm run build`, 출력 폴더 `dist`를 정한다. Node 버전은 `package.json`의 `engines`(24.x)를 따른다 |
| 캐시 | `assets/`는 1년 동안 바꾸지 않는 파일로, 나머지는 매번 확인하는 파일로 내준다. 실행 파일과 같은 규칙이다 |
| 보안 헤더 | 모든 응답에 `frame-ancestors 'none'`, `nosniff`, `no-referrer`를 붙인다 |
| `.canvacraft` 템플릿 | `application/octet-stream`으로 내주도록 적었다. Vercel은 모르는 확장자를 원래 이렇게 내주므로 덧댄 규칙이다. 실제 확인은 올린 뒤 템플릿을 열어 보는 것이다 |
| 파일 이름의 대소문자 | Vercel은 Linux에서 돌아 대소문자를 가린다. 배포본 시험의 서버도 대소문자를 가리게 바꿨다. 이 서버는 배포본 시험이 실제로 읽는 파일만 확인한다. 나머지는 2026-11-12 `dist`의 파일 안에 적힌 경로 1,506개를 실제 파일 이름과 대조해 모두 맞았다. 코드에서 조합하는 경로는 이 대조에 걸리지 않는다 |

`tests/contracts/vercelConfig.spec.ts`가 이 설정이 실행 파일의 규칙과 같은지 본다. Vercel이 이 설정을 실제로 어떻게 적용하는지는 올린 뒤 확인한다.

**처음 한 번(사용자)**

1. `vercel.json`이 main에 있는지 본다(2026-11-12에 합쳤다).
2. vercel.com에 GitHub 계정으로 들어가 `Add New` → `Project`에서 `easyCraft` 저장소(2026-11-12 전 이름 easyPoint)를 가져온다. Framework는 Vite로 잡히고 빌드 설정은 `vercel.json`을 따르므로 바꾸지 않는다.
3. Vercel은 기본 브랜치(main)를 정식 주소로 올린다. 2026-11-12 영상·애니메이션·만화와 `vercel.json`을 main에 합쳤으므로 Production 브랜치는 바꾸지 않는다.
4. 정식 주소에서 아래 "올린 뒤 확인"을 한다.

**알아 둘 점**

- 작품은 주소마다 따로 저장된다. 실행 파일(`127.0.0.1:47831`)에서 만든 작품은 Vercel 주소에 보이지 않는다. 옮기려면 원본 파일로 저장했다가 연다.
- Vercel은 브랜치와 커밋마다 미리보기 주소를 따로 만든다. 미리보기 주소에서 만든 작품은 정식 주소에 보이지 않는다. 아이에게는 정식 주소만 알려 준다.
- 주소를 아는 사람은 누구나 앱을 연다. 작품과 사진은 서버로 가지 않는다. 공개 전 결정 항목(§공개하기 전에 정할 것)은 그대로 남아 있다.
- Vercel Analytics 같은 추가 기능은 켜지 않는다. 외부로 나가는 요청이 생기고 앱의 보안 정책이 막는다.

## 올리기

1. `.sha256`으로 압축 파일을 확인한다.
2. 압축을 풀어 호스트의 대상 폴더에 올린다. 앞 버전의 압축 파일은 지우지 않고 보관한다.
3. 공개 주소에서 아래 확인을 한다.

## 올린 뒤 확인(약 5분)

1. 주소를 열어 시작 화면이 나오는지, 글씨가 Noto Sans KR로 보이는지 본다.
2. `슬라이드 만들기` → `새 작품`으로 들어가 슬라이드를 추가해 `저장됨`이 뜨는지, 새로고침해도 남는지 본다. `읽기 전용`이 뜨면 HTTPS가 아닌 것이다.
3. 템플릿 하나를 열어 본다.
4. PDF와 PowerPoint를 하나씩 내려받아 연다.
5. 발표를 시작하고 끝낸다.
6. 영상·애니메이션·만화 만들기에서 새 작품을 하나씩 열어 본다. 애니메이션은 `영상 (MP4)`, 만화는 `만화책 (PDF)`를 하나씩 내려받는다.
7. 개발자 도구의 Network에서 다른 주소로 나가는 요청이 없는지, Console에 Content Security Policy 오류가 없는지 본다.

## 되돌리기

1. 보관한 앞 버전 압축 파일의 내용으로 대상 폴더를 바꾼다.
2. 위 확인을 다시 한다.

작품은 사용자 브라우저에 있으므로 앱 파일을 바꿔도 지워지지 않는다. 지금까지 저장소 구조(`canvacraft` 데이터베이스 버전 1)와 문서 형식(`schemaVersion` 1)을 올린 적이 없어 앞 버전으로 되돌려도 저장된 작품을 연다. 예외로, v0.0.4에서 조각 빠르기를 쓴 영상 작품은 v0.0.3에서 열리지 않는다(v0.0.3이 `Clip.speed` 필드를 모른다). 애니메이션 작품은 따로 둔 데이터베이스(`canvacraft-animation` 버전 1)에 저장하므로, 애니메이션이 없는 앞 버전으로 되돌리면 애니메이션 작품은 보이지 않을 뿐 지워지지 않고 슬라이드·영상 작품은 그대로 열린다. 다시 새 버전으로 바꾸면 애니메이션 작품이 다시 보인다(자동 시험에서는 확인하지 않았다). 만화 작품도 같은 방식이다(데이터베이스 `canvacraft-comic` 버전 1). **이 값을 올리는 버전을 배포한 뒤에는 앞 버전이 새 형식의 작품을 열지 못하므로, 그 버전부터는 되돌리기 계획을 따로 세운다.**

앱을 연 채로 새 버전이 배포되면 그 탭에서 파일 내려받기 도구를 불러오지 못할 수 있다. 앱이 새로고침을 안내한다.

## 배포본 시험의 범위

`npm run test:release`는 `dist`를 `http://127.0.0.1:4180/canvacraft/`에서 내주고 Chromium으로 시험한다. 2026-11-12부터 이 서버는 Linux 호스트처럼 파일 이름의 대소문자를 가린다. 실제 호스트, HTTPS, CDN은 시험하지 않는다.
