# CanvaCraft 어린이 영상 편집기 기획과 단계별 개발 계획

작성일: 2026-11-07

상태: **구현 전 기획안.** 코드 수정, 라이브러리 설치, 브라우저 실행, 영상 출력 시험은 하지 않았다. 아래의 기술 후보와 코덱 지원 여부는 공식 문서·검색으로 조사한 것이며 이 PC에서 실행해 확인한 사실이 아니다. DEVELOPMENT_PLAN.md §2는 영상·음성을 후속 범위로 두었는데, 이 문서가 영상 모드에 대해 그 결정을 대체한다. 슬라이드 편집기 쪽 문서는 고치지 않는다.

## 3분 요약

**무엇을 만드는가.** 어린이가 휴대폰으로 찍은 영상을 가져와 자르고, 자막을 끌어다 놓아 몇 초 동안 보일지 정하고, **움직이는** 고양이·강아지 밈(투명 배경의 움직이는 스티커, 또는 소리가 든 짧은 밈 영상)을 얹어 YouTube에 올릴 MP4 한 개로 내보내는 편집기다. 밈이 움직인다는 것은 2026-11-07 사용자 결정이다. 로그인·서버·업로드 없이 브라우저 안에서 끝낸다(슬라이드 편집기와 같은 원칙).

**어디에 붙이는가.** 같은 앱·같은 주소(개발 5173, 실행 파일 47831)에 **시작 화면**을 추가한다. 큰 아이콘 두 개(슬라이드 만들기 / 영상 만들기)와 최근 작품이 보이고, 누르면 각 편집기의 작품 목록으로 들어간다. 영상 편집기의 화면 틀(상단 바·왼쪽 도구·가운데 작업 공간·아래 띠)은 슬라이드 편집기와 같은 모양을 유지해 아이들이 새로 배우지 않게 한다. 아래 띠만 슬라이드 목록 대신 **타임라인**이다.

**가장 큰 위험.** 브라우저에서 영상을 해독·다시 인코딩해 MP4로 묶는 일이다. 밈이 움직이므로 출력 때 프레임마다 본 영상 외에 밈 영상·움직이는 스티커의 프레임도 함께 해독해 겹쳐야 해 부담이 더 커진다. 후보는 WebCodecs API + Mediabunny(MP4·WebM 읽기·쓰기)이고, H.264·AAC 인코더가 없는 PC에서는 YouTube가 받는 WebM(VP9·Opus)으로 대신 낸다. 이 경로가 RAM 8GB PC에서 10분 영상을 다룰 수 있는지 **첫 구현 단계(V2)에서 먼저 측정**하고, 안 되면 범위를 줄인다. 아이폰 영상(HEVC)은 PC에 따라 못 읽을 수 있어 안내 문구가 필요하다.

**사용자가 정한 것.** §10의 7개는 2026-11-07에 모두 기본값으로 확정됐고 계약([video-contracts.md](video-contracts.md))에 옮겼다. 밈·효과음 자산을 어떻게 만들지만 V6 전까지 열려 있다. 인터넷에서 가져올 수 없고(저작권) 슬라이드의 내장 그림처럼 직접 만들거나 권리를 확인한 것만 쓴다.

## 1. 목표와 범위

### 어린이가 하는 일 (대표 흐름)

1. 시작 화면에서 **영상 만들기**를 누른다.
2. 휴대폰 영상 파일을 끌어다 놓거나 **영상 가져오기**로 고른다. 영상이 타임라인에 들어가고 바로 재생해 볼 수 있다.
3. 재생 막대를 움직여 자를 곳에 두고 **자르기**를 누른다. 필요 없는 조각을 눌러 **지우기**.
4. **자막**을 누르고 글씨를 치면 화면 가운데 자막 상자가 생긴다. 끌어서 원하는 자리에 놓고, 설정 줄의 **보이는 시간 3초 [−][+]**로 길이를 정한다. 자막은 지금 재생 막대가 있는 시점부터 보인다.
5. **밈**을 누르고 고양이·강아지 밈을 끌어 화면에 놓는다. 밈은 놓는 순간부터 움직이고, 자막과 같은 방법으로 보이는 시간을 정한다. 보이는 시간이 밈보다 길면 반복한다. 밈 영상에 든 소리와 효과음은 같이 난다.
6. **소리**에서 원본 소리 켜기/끄기와 배경음악을 고른다.
7. **내보내기**를 누르면 MP4 파일을 내려받는다. 보호자와 함께 YouTube에 올린다.

### 첫 버전에 넣는 것

| 기능 | 어린이에게 보이는 모습 | 제한 |
|---|---|---|
| 영상 가져오기 | 파일 선택·끌어놓기. 여러 개면 순서대로 이어 붙음 | MP4(H.264/AAC), WebM, 읽을 수 있으면 MOV(HEVC). 한 영상 최대 10분, 작품 전체 최대 10분 |
| 자르기 | 재생 막대 위치에서 조각을 둘로 나눔. 조각 끝을 끌어 앞뒤 다듬기. 조각 지우기·순서 바꾸기 | 조각은 한 줄로만 이어진다(겹치는 영상 트랙 없음) |
| 자막 | 글씨 상자를 끌어 놓고 보이는 시간을 초 단위로 정함. 글꼴 6종·크기·색·굵게·정렬은 슬라이드와 같음 | 글자 애니메이션·자동 자막(음성 인식) 없음 |
| 밈 (움직이는 스티커) | 투명 배경에서 움직이는 고양이·강아지 그림. 끌어 놓고 크기 조절, 보이는 시간 지정. 보이는 시간 동안 반복 재생 | 직접 만들거나 권리를 확인한 자산만. 파일 형식(애니메이션 WebP·APNG 또는 투명 WebM)은 V2에서 결정 |
| 밈 (짧은 영상) | 소리가 든 1~10초짜리 사각형 밈 영상. 본 영상 위에 작은 창으로 겹침. 끌어 놓고 크기 조절, 보이는 시간 지정, 반복 | 앱이 제공하는 밈 영상만. 아이가 가진 영상 둘을 겹치는 기능(PIP)은 아니다. 같은 시점에 겹치는 밈 영상은 2개까지 |
| 효과음 | 밈에 붙은 소리(야옹, 멍, 띠용 등). 밈이 나타나는 순간 1회 재생. 끄기 가능 | 밈과 함께 제공하는 짧은 소리만. 자유 녹음 없음 |
| 소리 | 원본 소리 켜기/끄기와 크기(0·50·100%), 배경음악 고르기와 크기 | 제공 곡만. 음악 파일 가져오기는 후속 |
| 미리보기 | 큰 재생 버튼, 시간 표시(0:05 / 1:20), 재생 막대 끌기 | 미리보기는 실시간 재생이 안 되면 끊김을 허용하되 출력물은 정확해야 한다 |
| 작품 저장 | 변경 1초 뒤 자동 저장, 작품 목록에서 다시 열기 | 영상 원본 파일은 브라우저 저장소에 복사해 둔다(§6). 원본 내려받기(.canvavideo)는 영상 크기 때문에 수 GB가 될 수 있어 안내가 붙는다 |
| 내보내기 | 한 버튼. 진행률·취소. 끝나면 MP4 내려받기와 'YouTube에 올리는 방법' 안내 | 해상도·비트레이트 선택 화면 없음. 앱이 정한다(§7) |
| 되돌리기 | Ctrl+Z / 버튼 | 슬라이드와 같은 명령·취소 구조 |

### 넣지 않는 것 (후속 범위)

아이가 가져온 영상 둘을 겹치는 PIP(밈 영상 겹치기는 포함), 장면 전환 효과, 필터·색 보정, 속도 조절, 녹화·녹음, 음악 파일 가져오기, 자동 자막, 손그림 애니메이션, YouTube 직접 업로드(네트워크 요청 금지 계약 §8), 공유 링크, 휴대폰 세로 화면용 UI. 사진(이미지 파일)을 조각으로 넣는 것은 간단하지만 첫 버전에서는 빼고 V5 이후 결정한다.

### YouTube 업로드에 대한 안내

앱은 파일만 만든다. 업로드는 보호자가 브라우저의 YouTube 스튜디오에서 한다. 한국에서 만 14세 미만은 자기 계정을 만들 수 없으므로 안내 문구는 "보호자 계정으로 올리기"로 쓴다. 이 안내는 내보내기 완료 창에 한 문단으로만 넣고 외부 링크는 넣지 않는다.

## 2. 시작 화면과 모드 분리

### 결정: 시작 화면 + 모드별 작품 목록

| 화면 | 내용 |
|---|---|
| 시작 화면 | 가운데 큰 타일 2개: **슬라이드 만들기**(보라), **영상 만들기**(주황 등 다른 색). 아래에 '최근 작품' 6개까지 두 종류를 섞어 최근순으로 표시하고 카드에 종류 아이콘을 붙인다. 카드를 누르면 바로 그 편집기로 들어간다 |
| 슬라이드 작품 목록 | 지금의 `Home.tsx` 그대로. 상단 바 왼쪽에 시작 화면으로 가는 버튼을 추가한다 |
| 영상 작품 목록 | 같은 배치. 템플릿 대신 '처음이면 이렇게' 안내 카드 1~2개(가져오기 → 자막 → 내보내기 그림) |

사용자가 말한 "프로그램 실행하듯 아이콘으로 고르기"가 이 구조다. 대안으로 작품 목록 하나에 두 종류를 섞고 '새 작품' 버튼만 두 개로 나누는 방법이 있는데, 작품 목록에 '내 작품' 외에 템플릿·안내가 종류별로 달라 한 화면이 복잡해지므로 택하지 않는다.

### 기존 시작 규칙과의 우선순위

지금 `src/app/App.tsx`는 새로고침이면 `sessionStorage`에 기억한 작품으로 돌아가고, 저장 작품이 있으면 작품 목록, 없으면 새 작품으로 바로 들어간다. 바뀌는 규칙:

1. 기억한 작품이 있으면 종류에 맞는 편집기로 바로 돌아간다(새로고침 복원 유지). 기억 값에 종류를 함께 저장한다(`canvacraft.current-project` 값 형식 변경 → 옛 값은 슬라이드로 해석).
2. 기억한 작품이 없으면 **항상 시작 화면**이다. 저장 작품이 없을 때 새 슬라이드 작품으로 바로 들어가던 규칙은 없어진다.
3. `tests/e2e/flow.spec.ts`·`home.spec.ts`, 배포본 시험 `tests/release`(12건), 실행 파일 시험 `scripts/test-exe.mjs`가 "빈 상태면 바로 편집기"를 전제하면 시작 화면에서 타일을 한 번 누르는 단계를 시험에 추가한다. 이 변경은 V3에서 하고, 그 뒤 `npm test`·`npm run test:release`·`npm run test:exe`가 다시 통과해야 한다.

### 코드 배치

한 SPA(`index.html`) 안에서 `Screen` 상태에 `start`, `video-home`, `video-editor`를 추가한다. 영상 편집기 코드와 미디어 라이브러리는 PPT·PDF 출력 도구처럼 `import()`로 필요할 때 받는다. 그래서 슬라이드만 쓰는 아이의 첫 로딩 크기는 늘지 않는다. 별도 `video.html`로 나누지 않는 이유는 새로고침 복원·CSP·실행 파일 서빙 규칙을 하나로 유지하기 위해서다. 공유하는 코드: `TopBar` 틀, `ToolRail`, `Icon`, `Menu`, 글씨 입력(`TextEditor`), 글씨 줄 배치(`layoutText`)·글꼴 등록표, 선택·크기 조절 계산(`geometry.ts`), 자동 저장 예약(`autosave.ts`), 잠금(`locks.ts`).

## 3. 영상 편집 화면 (UI_REFERENCE.md의 틀을 유지)

| 영역 | 영상 편집기에서의 내용 |
|---|---|
| 상단 바 | 같은 그라데이션. 왼쪽: 작품 목록으로, 파일 메뉴(새 작품 / 원본 열기 / 원본 저장 / 이 컴퓨터에 저장), 되돌리기·다시 실행, 작품 이름·저장 상태. 오른쪽: **내보내기** 버튼 하나(발표·공유 버튼 없음) |
| 왼쪽 도구 모음 | 위에서 **영상 / 자막 / 밈 / 소리** 4개. 그리기·배경·템플릿은 없다 |
| 왼쪽 세부 패널 | 영상: 가져오기 버튼, 가져온 영상 목록(길이 표시, 다시 넣기). 자막: 자막 추가 버튼, 글씨 스타일 예시 3개(크게·보통·말풍선). 밈: 검색·분류 칩(고양이 / 강아지 / 리액션 / 효과)과 카드(카드 위에 마우스를 올리거나 누르면 움직임 미리보기), 최근 사용. 소리: 원본 소리 켜기·크기, 배경음악 카드와 크기 |
| 중앙 작업 공간 | 16:9(또는 9:16) 미리보기. 영상 위에 자막·밈을 겹쳐 그린다. 아래에 큰 재생/일시정지, 시간 표시, 재생 막대. 선택 테두리·손잡이는 슬라이드와 같은 보라색 |
| 요소 설정 줄 | 자막 선택: 글꼴·크기·굵게·색·정렬 + **보이는 시간 N초 [−][+]** + **지금부터**(시작을 재생 막대로) + 복제·삭제. 밈 선택: 보이는 시간, 지금부터, 소리 켜기/끄기, 앞뒤, 복제·삭제(반복 여부는 묻지 않고 늘 반복). 조각 선택: 자르기(여기서), 지우기, 소리 켜기/끄기 |
| 하단 타임라인 | 두 줄. 위 줄은 영상 조각 띠(미리보기 그림 + 길이), 아래 줄은 자막·밈 막대(시작·끝을 끌어 조절). 세로 빨간 재생 막대. 오른쪽 아래에 타임라인 확대/축소 |

어린이용 단순화 규칙: 숫자 입력 칸을 두지 않고 초 단위 −/+ 버튼과 끌기만 쓴다. 보이는 시간 기본 3초, 최소 1초, 최대 60초. 자막·밈이 영상 끝을 넘으면 영상 끝까지로 줄이고 안내한다. 한 시점에 보이는 자막·밈 수는 제한하지 않되 작품 전체 요소 상한(§5)을 둔다. 터치에서는 조각 순서 변경을 끌기 대신 메뉴(왼쪽으로/오른쪽으로)로 한다(슬라이드 목록과 같은 결정).

## 4. 데이터 구조와 명령

슬라이드와 같은 원칙: 문서는 변경 불가능한 값, 바꾸는 곳은 dispatch·undo·redo 하나, 화면은 임시 끌기 값만 `preview`로 쥐고 손을 떼면 명령 하나를 보낸다.

| 객체 | 필드 |

| Clip | id, mediaId, inMs, outMs(원본 안의 구간), muted |
| Overlay(공통) | id, type, startMs, durationMs, x, y, width |
| CaptionOverlay | 공통 + text, fontId, fontSize, bold, color, align, lineHeight, **backdrop**('none' / 'band' 반투명 띠) |
| MemeOverlay | 공통 + height, memeId(앱 내장 밈 목록의 ID), memeKind('sticker' 투명 애니메이션 / 'clip' 사각형 밈 영상), soundOn(밈 영상의 소리와 효과음을 함께 켜고 끔). 재생은 startMs부터 밈 길이 단위로 반복하며 반복 여부는 저장하지 않는다 |
| Meme(내장 목록) | id, kind, 파일 경로, durationMs, width, height, soundId(없을 수 있음), 분류·검색 태그, 라이선스. `public/memes/manifest.json`에 두고 `library.ts`처럼 해시로 검증한다 |
| AudioSettings | originalVolume(0·0.5·1), musicId(없을 수 있음), musicVolume |
| Media | id=파일 바이트 SHA-256, mime, durationMs, width, height, fps, hasAudio, byteLength, codec 문자열 |
| VideoProjectSummary | projectId, kind='video', title, updatedAt, revision, durationMs, 첫 프레임 미리보기 |

좌표는 슬라이드와 같은 **논리 1280×720**(세로는 720×1280)으로 두고 출력 때 1.5배로 1920×1080에 그린다. 그래서 `geometry.ts`의 선택·이동·크기 계산, `layoutText`, 글꼴 등록표를 다시 쓸 수 있다는 것이 설계 가정이다. 다만 `geometry.ts`, `SelectionLayer`, `validate.ts`는 `LIMITS.slideWidth/Height`를 직접 읽으므로 그대로 꽂아 쓸 수는 없고, 캔버스 크기를 인자로 받게 바꾸는 작업이 V3에 들어간다(세로 720×1280 때문). 1.5배 확대 때 글씨 가장자리·선 굵기가 출력물에서 어떻게 보이는지는 V2에서 실제 프레임으로 확인한다. 타임라인의 시간은 정수 밀리초다. 조각의 작품 안 위치는 앞 조각 길이의 합으로 계산하고 저장하지 않는다(순서 정보를 두 곳에 두지 않는 슬라이드 규칙과 같다).

### 명령 (취소 단위 1회씩)

renameProject, addClip(media, 끝에 추가), splitClip(clipId, atMs), trimClip(clipId, inMs, outMs), deleteClip, reorderClip, setClipMuted, addCaption, updateCaption(글·서식·폭), addMeme, setOverlayTime(startMs, durationMs), moveOverlay, resizeOverlay(자막은 폭·글씨 크기, 밈은 폭·높이 비율 유지), reorderOverlay(앞뒤), duplicateOverlay, deleteOverlay, setMemeSound, setAudio(원본 음량·배경음악·음악 음량). 미디어 등록은 addClip 안에서 함께 처리하고 되돌리면 등록도 돌아간다(슬라이드의 addImage와 같은 방식). 실패 코드는 기존 `ErrorCode`에 `MEDIA_UNSUPPORTED`(읽을 수 없는 코덱·형식), `ENCODER_UNAVAILABLE`(출력 코덱 없음)을 더한다.

`src/state/store.ts`는 `Project`·`Slide`에 묶여 있어(`nearestSlide`, `estimateBytes`) 그대로 재사용할 수 없다. V3에서 **문서 타입을 매개변수로 받는 공통 저장소**로 일반화하되, 슬라이드 쪽 시험(`tests/contracts`, `flow.spec.ts`)이 바뀌지 않고 통과하는 것을 조건으로 한다. 일반화가 어려우면 같은 규칙의 `videoStore.ts`를 따로 두고 중복을 기록한다.

## 7. 가져오기·미리보기·내보내기 기술 후보

### 왜 WebCodecs인가

| 방식 | 판단 | 이유 |
|---|---|---|
| **WebCodecs + 컨테이너 라이브러리(Mediabunny 후보)** | **채택 후보, V2에서 검증** | 브라우저 내장 해독·인코더(하드웨어 가속 포함)를 쓰고, 라이브러리는 MP4/WebM 읽기·쓰기만 맡는다. 추가 네트워크·서버 없음. Mediabunny는 MP4·MOV·WebM 읽기·쓰기와 WebCodecs 연결을 제공하는 TypeScript 라이브러리로 조사됐다(MPL-2.0). 설치·동작은 미확인 |
| ffmpeg.wasm | 채택하지 않음 | 다중 스레드판은 SharedArrayBuffer가 필요해 COOP/COEP 응답 헤더를 요구한다. 실행 파일(`CanvaCraftLauncher.cs`)과 정적 호스트 모두 헤더를 바꿔야 하고, 단일 스레드판은 느리다. 번들도 30MB 안팎이다 |
| MediaRecorder로 캔버스 녹화 | 채택하지 않음 | 실시간 재생 속도로만 만들어져 3분 영상에 3분이 걸리고, 프레임 시각이 흔들린다. WebM만 나온다 |

### 가져오기

파일 헤더로 형식을 확인 → 컨테이너 읽기로 트랙·길이·코덱을 얻음 → `VideoDecoder.isConfigSupported()`로 이 PC가 해독할 수 있는지 확인 → 가능하면 첫 프레임을 뽑아 미리보기 → 저장소에 복사. 해독할 수 없으면 "이 영상은 이 컴퓨터에서 읽을 수 없어요. 휴대폰 설정에서 '호환성 높은 형식(MP4)'으로 다시 찍거나 변환해 주세요"로 안내하고 작품은 건드리지 않는다. 아이폰 기본 설정의 HEVC(H.265)는 Windows의 Chrome·Edge에서 GPU와 HEVC 확장 유무에 따라 되기도 안 되기도 한다고 조사됐다. 지원된다고 약속하지 않고 안내로 처리한다. 사진 EXIF처럼 영상 메타데이터(위치 정보 등)는 출력 파일에 넣지 않는다.

### 미리보기

재생 중에는 `<video>` 요소(Blob URL)를 숨겨 두고 그 프레임을 캔버스에 그린 뒤 자막·밈을 겹친다. 재생 막대를 끌 때는 해당 시각으로 seek한 프레임을 쓴다. 조각 경계에서는 다음 조각의 `<video>`를 미리 준비한다. 밈 영상은 밈마다 숨긴 `<video>`를 하나씩 두고 `(현재 시각 − startMs) mod 밈 길이`로 맞춘다. 움직이는 스티커는 `<img>`로 두면 타임라인과 프레임을 맞출 수 없으므로 `ImageDecoder`로 프레임을 미리 풀어 두고 시각에 맞는 프레임을 그린다(애니메이션 WebP·APNG). 효과음·배경음악·밈 영상 소리는 Web Audio로 같은 시계에 맞춘다. 미리보기 프레임이 출력과 1프레임 어긋나는 것은 허용하고, 자막 시작·끝 시각은 출력에서 정확해야 한다.

### 내보내기

| 항목 | 결정 |
|---|---|
| 처리 위치 | **Worker**에서 해독 → 프레임마다 OffscreenCanvas에 영상 + 자막·밈을 그림 → `VideoEncoder` → 컨테이너 쓰기. 밈 영상은 보이는 구간에만 둘째 `VideoDecoder`를 열어 같은 시각의 프레임을 받고, 움직이는 스티커는 프레임을 한 번 풀어 재사용한다. 반복 재생은 밈 길이로 나눈 나머지 시각의 프레임을 쓴다. 메인 화면은 진행률·취소만. 계약 §8의 "worker는 쓰지 않는다"는 영상 모드에 대해 **개정**한다. 배포 CSP는 `default-src 'none'; script-src 'self'`라 같은 origin Worker는 허용되지만, WASM을 쓰는 라이브러리면 `script-src`에 `'wasm-unsafe-eval'`이 필요하다. `npm run test:release`가 이를 확인하는 자리다 |
| 해상도·비율 | 1920×1080(가로) 또는 1080×1920(세로). 원본이 더 작으면 늘리지 않고 그대로, 비율이 다르면 검은 여백 |
| 프레임률 | 첫 영상의 프레임률(24·25·30). 다른 조각은 가장 가까운 프레임으로 맞춤. 60fps 원본은 30으로 줄임 |
| 형식 선택 규칙 | **쌍으로 정한다.** H.264(High)와 AAC가 **둘 다** `isConfigSupported()`를 통과하면 MP4(H.264+AAC). 하나라도 안 되면 파일 전체를 WebM(VP9+Opus)으로 낸다. WebM에는 H.264를 넣을 수 없고, MP4에 H.264+Opus를 넣은 파일을 YouTube가 받는지 확인하지 않았기 때문이다. VP9·Opus는 Chrome이 소프트웨어로 항상 제공하므로 대체 경로는 늘 열려 있다. V2에서 코덱 하나씩이 아니라 이 두 조합으로 시험한다 |
| 영상 코덱 | 비트레이트는 1080p30 기준 10Mbps VBR을 시작값으로 두고 V2 결과로 조정 |
| 소리 | 조각 원본 소리 + 밈 영상 소리(반복 포함) + 효과음 + 배경음악을 Web Audio(OfflineAudioContext)로 48kHz 스테레오로 섞음 → `AudioEncoder` AAC 192kbps 또는 Opus |
| 파일 | MP4 또는 WebM 한 개. YouTube는 둘 다 받는다. 결과 창에 형식을 적고 WebM이면 "YouTube에 올릴 수 있어요"를 함께 쓴다 |
| 진행·취소 | 장별 진행률처럼 초 단위 진행률. 취소하면 부분 파일을 내려주지 않음. 내보내기 중 편집은 스냅샷에 섞지 않음 |
| 메모리 | 프레임을 한 번에 몇 개만 쥐고 `VideoFrame.close()`를 바로 호출. 출력 바이트는 저장소 파일로 흘려 쓰고 끝나면 Blob으로 내려받음(수백 MB를 메모리에 모으지 않음) |

YouTube 권장값(MP4, H.264, AAC, 1080p에서 8~10Mbps 안팎, 스테레오 384kbps)은 Google 도움말에 있으나 캐시된 버전마다 숫자가 달라 V2에서 현재 페이지 값을 다시 확인한다. 조사에서 Windows의 Chrome이 AAC·H.264 **인코딩**을 어느 PC에서 제공하는지는 확정하지 못했다(Chromium이 Windows 미디어 기반 AAC 인코더를 쓴다는 보도와 "`isConfigSupported()`로 확인하라"는 권고만 확인). 그래서 WebM 대체 경로가 필수다.

  - 출력물 확인: 만든 MP4·WebM을 Windows 미디어 플레이어·Chrome에서 열고 길이·프레임 수·소리 확인. 가능하면 보호자 계정으로 YouTube 비공개 업로드 1회(사용자가 수행).
  - 자막 겹치기: 논리 1280×720 자막을 1.5배로 1080p 프레임에 그린 결과를 눈으로 확인.
  - 움직이는 밈 형식: ① 애니메이션 WebP·APNG를 `ImageDecoder`로 풀어 프레임 시각을 얻을 수 있는지와 메모리(512×512×5초×24fps ≈ 120프레임), ② 투명 WebM(VP9 알파)을 WebCodecs `VideoDecoder`가 알파 채널까지 돌려주는지(미확인. 안 되면 ①로 확정). 밈 영상 겹치기: 본 영상 1080p + 밈 영상 720p 2개를 동시에 해독할 때 출력 시간·메모리 증가분과 소리 섞기 정확도.
  - 저장: 500MB 파일의 IndexedDB Blob 저장 vs OPFS 쓰기·부분 읽기·삭제 시간, 용량 추정 값.
  - Worker + CSP: 배포본(`npm run build` 결과)에서 Worker와 라이브러리가 CSP 오류 없이 도는지, 실행 파일(`npm run exe`)에서도 같은지.
  - Playwright: 번들 Chromium은 H.264·AAC가 없다. 자동 시험은 WebM(VP9/Opus) fixture로 하고, MP4 경로는 `channel: 'msedge'` 또는 `'chrome'` 프로젝트를 추가해 사용자 PC에서 돈다. 두 가지 방식 모두 동작 여부를 여기서 확인한다.
- 산출물: 측정 수치·스크린샷·브라우저 버전·라이브러리 버전과 라이선스 기록(`docs/VIDEO_PHASE2_RESULTS.md`), 잠금 파일 고정.
- 완료 기준: 1분 영상을 가져와 자막 1개와 움직이는 밈 1개(스티커·영상 각 1개)를 얹어 MP4 또는 WebM으로 내보낸 파일이 실제 플레이어에서 재생되고 밈이 움직인다. 10분 영상의 출력 시간과 메모리가 §9 목표 안이다.
- 중단 조건: 8GB PC에서 10분 영상이 목표를 넘으면 전체 길이 상한을 줄인다(5분 등). H.264·AAC가 두 PC 모두에서 안 되면 WebM만 공식 지원으로 바꾸고 안내를 수정한다. 해독이 전혀 안 되는 형식은 미지원 목록에 올린다. 밈 영상 둘을 겹친 출력이 목표를 크게 넘으면 동시 밈 영상을 1개로 줄인다.

### V3. 시작 화면·모드 분리·문서·명령·저장 틀 (2~3일)

- 작업: 시작 화면, 종류별 작품 목록, `Screen` 확장, 기억 값 형식 변경, 공통 저장소 일반화(또는 videoStore. 이 경우 AGENTS.md의 "문서를 바꾸는 곳은 store.ts뿐" 문장을 함께 고친다), 캔버스 크기 인자화(§4), VideoProject 타입·검사·명령 전체·취소, 영상 저장소와 자동 저장 연결, `.canvavideo` 왕복.
- 산출물: 명령별 실행→취소→다시 실행 계약 시험, 공통 영상 fixture(짧은 WebM 2개 + 문서), 시작 화면 e2e.
- 완료 기준: 시작 화면 단계를 추가해 고친 시험을 포함해 슬라이드 쪽 시험 전체가 통과한다. 시작 화면에서 두 편집기에 들어가고 새로고침해도 하던 작품으로 돌아온다. 영상 문서가 저장·재열기·원본 왕복된다.

### V4. 가져오기·미리보기·타임라인·자르기 (3~4일)

- 작업: 파일 선택·끌어놓기, 형식 검사와 미지원 안내, 저장소 복사와 용량 안내, 타임라인 띠·재생 막대·확대, 재생·일시정지·seek, 자르기·다듬기·지우기·순서.
- 완료 기준: 두 영상을 이어 붙여 자른 결과를 재생하면 조각 경계에서 멈추지 않는다(끊김 0.2초 이내 허용은 V2 측정으로 조정). 되돌리기 한 번에 자르기 한 번이 돌아간다. 손상 파일은 작품을 건드리지 않는다.

### V5. 자막 (2~3일)

- 작업: 자막 추가·입력(기존 `TextEditor`·IME 규칙), 끌기·크기, 보이는 시간 −/+·지금부터·타임라인 막대 끌기, 반투명 띠 배경, 설정 줄.
- 완료 기준: 한글 조합 중 Enter·Esc·재생이 글자를 중복·소실시키지 않는다(슬라이드 Phase 6 시험을 재사용). 자막 시작·끝이 재생과 타임라인에서 같은 시각이다. 영상 끝을 넘는 자막은 줄어들고 안내된다.

### V6. 움직이는 밈·효과음·소리 (4~6일)

- 작업: 밈 패널(검색·분류·최근 사용·움직임 미리보기, 기존 `library.ts` 형식 확장), 끌어 놓기·크기·보이는 시간·반복, 움직이는 스티커 프레임 재생(`ImageDecoder`), 밈 영상 둘째 `<video>` 동기와 소리, 효과음 재생 시각 동기, 동시 밈 수 상한 안내, 원본 소리 켜기/끄기·크기, 배경음악 선택·크기, Web Audio 미리보기.
- 자산: 움직이는 스티커 최소 16종(고양이 6·강아지 6·리액션 4), 밈 영상 최소 8종(소리 포함), 효과음 12개, 배경음악 4곡을 §10의 결정에 따라 확보하고 `docs/asset-licenses.md`에 기록한다. 확보 전에는 자리 표시 자산(단색 사각형이 움직이는 WebP, 무음 짧은 WebM)으로 개발한다.
- 완료 기준: 밈이 나타나는 프레임, 밈의 움직임 단계, 효과음·밈 소리 시작이 미리보기와 출력에서 같은 시각(±1프레임)이다. 반복 경계에서 프레임이 건너뛰지 않는다. 소리 끄기가 출력에 반영된다.

### V7. 내보내기 (3~5일)

- 작업: Worker 출력 파이프라인, 소리 섞기, H.264/AAC → VP9/Opus 대체 선택, 진행률·취소·실패 안내, 결과 창과 YouTube 안내, 저장소로 흘려 쓰기.
- 완료 기준: 조각 3개·자막 5개·밈 3개(스티커 2·영상 1, 한 구간은 겹침)·배경음악이 든 3분 작품을 내보낸 파일을 Windows 미디어 플레이어와 Chrome에서 재생하고, 자막·밈 시각이 타임라인과 같다. 출력 중 편집이 파일에 섞이지 않는다. 취소 후 다시 내보낼 수 있다. 사용자가 보호자 계정으로 비공개 업로드해 YouTube가 처리 완료하는 것을 확인한다(사람 확인).

### V8. 통합·실행 파일·배포 준비·어린이 관찰 (3~5일)

- 작업: 실행 파일 MIME·CSP 반영과 `npm run test:exe`, 배포본 시험, 8GB PC 측정, 안내 문구 점검, USER_GUIDE·RELEASE 갱신, 어린이 관찰(보호자·교사 입회, 못 구하면 미실시로 기록).
- 완료 기준: §9의 대표 시나리오를 배포본과 실행 파일에서 통과한다.

단순 합계 21~33 작업일이며 확정 일정이 아니다. V2 결과로 다시 산정한다.

## 9. 검증 기준과 성능 목표

| 항목 | 초기 목표와 확인 방법 |
|---|---|
| 기준 기기 | RAM 8GB 보급형 Windows PC, Chrome 또는 Edge 최신. 개발 PC 수치만으로 통과 처리하지 않는다 |
| 내보내기 시간 | 1080p30 영상 길이의 2배 이내(10분 영상 20분). 하드웨어 인코더가 있으면 1배 이내를 기대하되 보장하지 않음 |
| 내보내기 메모리 | 브라우저 탭 1.5GB 이내. 성능 패널로 측정 |
| 가져오기 | 500MB 파일 저장소 복사 30초 이내. 첫 프레임 미리보기 3초 이내 |
| 미리보기 | 1080p 원본 재생 중 자막·밈 겹치기로 프레임 누락이 눈에 띄지 않음(개발 PC). 8GB PC는 측정 후 결정 |
| 조작 반응 | 자막·밈 선택·끌기 100ms 이내(슬라이드와 같음) |
| 시각 정확도 | 자막·밈 시작·끝, 밈의 움직임 단계, 효과음이 출력에서 ±1프레임. 출력 파일을 다시 해독해 해당 프레임의 픽셀을 확인하는 자동 시험 |
| 밈 겹치기 부담 | 밈 영상 2개가 겹친 구간이 전체의 20%인 3분 작품의 출력 시간이 밈 없는 작품의 1.5배 이내 |

자동 시험 구조: 계약 시험(명령·취소·검사·시간 계산), e2e(시작 화면·가져오기·타임라인·자막·밈·내보내기 왕복, WebM fixture, 번들 Chromium), 코덱 시험(`channel: 'msedge'` 프로젝트, MP4 fixture, 사용자 PC에서만), 배포본·실행 파일 시험. 실제 플레이어 재생과 YouTube 업로드는 자동 시험만으로 통과 처리하지 않는다.

대표 사용자 시나리오:

1. 시작 화면에서 영상 만들기 → 휴대폰 MP4 2개 가져오기 → 두 번째를 10초 자르고 뒤쪽 지우기.
2. 자막 두 개(한글·이모지 포함)를 서로 다른 시각에 3초·5초로 놓고 위치·크기 바꾸기.
3. 움직이는 고양이 스티커와 소리 든 강아지 밈 영상을 같은 구간에 넣고 소리를 한 번 끄고 다시 켜기. 보이는 시간을 밈 길이보다 길게 해 반복 확인.
4. 배경음악을 고르고 원본 소리를 50%로.
5. 새로고침·브라우저 재시작 뒤 복원 확인, 원본 `.canvavideo` 저장 후 다른 프로필에서 열기.
6. 내보내기 → 파일 재생 → 보호자 계정 비공개 업로드.
7. 읽을 수 없는 HEVC 파일, 저장 공간 부족, 내보내기 취소, 10분 상한 초과, 둘째 탭 읽기 전용을 각각 시험.
