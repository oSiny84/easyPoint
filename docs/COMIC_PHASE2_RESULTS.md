# 만화 만들기 K2 확인 결과

작성일: 2026-11-12. 기획은 [COMIC_PLAN.md](COMIC_PLAN.md) §8 K2, 계약은 [comic-contracts.md](comic-contracts.md)다.

## 요약

| 확인한 것 | 결과 | 판단 |
|---|---|---|
| 쪽 조립(세 배치) | 제품 함수 `composePage`가 번들 Chromium에서 칸·테두리·제목·쪽 번호를 계약 §3대로 그렸다. 그림을 직접 열어 확인했다 | 그대로 쓴다 |
| 만화책 PDF 시간과 크기 | 100칸 작품이 0.7~1.7초, 5.4~12.1MB | 목표(30초 이내) 안이다. 칸 그림 배율을 올리거나 `grid8`을 뺄 까닭이 없다 |
| 만화 그림 묶음 | 말풍선 9종·효과 그림 12종을 만들어 한 장에 늘어놓고 확인했다 | 그대로 쓴다. 넓은 말풍선은 따로 두지 않는다 |
| 끄는 동안 짝 글씨 | `SlideCanvas`는 임시 요소를 가운데 레이어에 그린다. 요소 몇 개를 더 그리고 원래 자리에서 빼는 변경이면 된다 | 선택 인자 `companions`를 연다(계약 §9) |
| 인쇄 | 하지 않았다 | **미확인.** 사용자가 `artifacts/comic-phase2/comic-grid4.pdf` 같은 파일을 실제 프린터로 뽑아 봐야 한다 |

중단 조건(인쇄에서 글씨가 읽기 어려움)은 인쇄를 하지 않아 판정하지 못했다. 화면에서 본 쪽 그림에서는 8칸 배치의 36 크기 대사도 읽힌다.

## 환경

개발 PC(논리 코어 16, RAM 32GB), 번들 Chromium 158.0.8127.18, 시험 페이지 `comic-probe.html`(`src/comicprobe/main.ts`), 실행 `npx playwright test -c playwright.comic-phase2.config.ts`. 시험 페이지와 시험은 제품 코드가 아니며 `npm test`에서 빠진다. 결과 파일은 `artifacts/comic-phase2/`(Git 제외)에 남는다.

시험 문서: 칸마다 색 배경, 손그림 선 20개(점 40개씩), 말풍선 그림 하나와 두 줄 대사, 큰 효과 글씨 하나. "사진 포함"은 세 칸에 하나꼴로 1600×1200 JPEG 사진을 더한 것이다.

## 쪽 조립

| 배치 | 쪽 그림 크기(포인트당 3픽셀) | 조립 시간(내려받기 배율) | 조립 시간(만화 보기 배율 2) | PNG 크기 |
|---|---|---|---|---|
| `rows3` | 1785 × 2526 | 126ms(첫 호출, 글꼴 로딩 포함) | 16ms | 0.55MB |
| `grid4` | 2526 × 1785 | 24ms | 16ms | 0.69MB |
| `grid8` | 1785 × 2526 | 52ms | 23ms | 0.85MB |

만화 보기에서 쪽을 넘길 때 기다림이 없을 수준이다. 쪽 그림을 미리 만들어 두는 캐시는 두지 않는다.

## 만화책 PDF (100칸)

| 배치 | 쪽 수 | 그림만: 시간 / 크기 | 사진 포함: 시간 / 크기 |
|---|---|---|---|
| `rows3` | 34 | 1.5초 / 10.7MB | 1.7초 / 12.1MB |
| `grid4` | 25 | 1.2초 / 9.1MB | 1.4초 / 10.3MB |
| `grid8` | 13 | 0.7초 / 5.4MB | 0.9초 / 6.1MB |

쪽 수는 모두 `⌈100 ÷ 한 쪽의 칸 수⌉`와 같았다.

## 정한 것

1. 쪽 그림 배율은 내려받기 3, 만화 보기 2로 한다(계약 §3).
2. 세 배치를 모두 넣는다.
3. 말풍선은 가로세로 비율이 고정이다. 긴 대사는 말풍선을 키우거나 해설 상자를 쓴다. 넓은 말풍선 그림은 만들지 않는다.
4. 끄는 동안 짝 글씨를 함께 그린다.

## 확인하지 못한 것

- 실제 프린터 인쇄(여백, 선명도).
- RAM 8GB PC에서의 시간.
- 어린이가 말풍선 그림을 마음에 들어 하는지.
