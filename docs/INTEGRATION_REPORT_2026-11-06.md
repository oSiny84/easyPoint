# 통합 시험 보고서 (Phase 10)

작성: 2026-11-06. 대상: `npm run build` 결과(`dist`)를 하위 경로에서 내준 배포본. 환경: 개발 PC, Windows 11, Playwright Chromium, PowerPoint 16.0(COM). 재실행은 `npm run test:release`다.

## 결론

**자동으로 확인할 수 있는 범위에서는 대표 시나리오 7개를 모두 통과했다. 공개 배포 준비가 끝난 것은 아니다.** 어린이 사용성 관찰을 하지 않았고, 실제 기기 확인과 이름·화면 권리 검토가 남아 있다. 계획의 완료 기준인 "실제 환경"을 일부만 충족한다.

| 구분 | 상태 |
|---|---|
| 필수 수정으로 남은 결함 | 없음 |
| 점검 중 찾아 고친 결함 | 6건 |
| 사람이 확인해 닫은 항목 | 3건(2026-11-06 사용자 확인) |
| 사람이 확인해야 남은 항목 | 4건 |
| 어린이 사용성 관찰 | **미실시** |

| 시나리오 | 결과 | 확인 방법과 한계 |

| 4. 장 복사, 둘째 장 글씨만 변경, 순서 변경 | 통과 | 복사본만 바뀌고 순서가 바뀜을 저장소에서 확인 |

| 7. 누락 자산 | 통과 | 사진이 빠진 원본 거부, 지금 작품 유지 |
| 7. 긴 한글 문장 | 통과, 제약 있음 | 줄은 상자 폭에 맞게 나뉜다. 슬라이드 아래로 넘친 글씨는 잘려 보인다(아래 제약) |
| 7. 출력 취소 | 통과 | 도중 취소 후 파일 없음, 다시 받기 성공 |

## 큰 문서 측정

20장, 장당 요소 50개(사진 3, 글씨 25, 획 22). **개발 PC 값이고 RAM 8GB 기준 기기의 값이 아니다.** 사진이 단순한 합성 그림이고 모든 장의 사진이 같아 파일 크기는 실제보다 작다. 서로 다른 합성 사진 60장의 크기는 PROGRESS.md §3에 있다(편집용 PPT 45.7MB, 5초).

| 항목 | 값 | 목표 |
|---|---|---|
| 열기와 첫 저장 | 209ms | |
| 장 전환 평균 | 47ms | |
| 요소 선택 | 15ms | 100ms 이내 |
| 끌기 뒤 저장 표시 | 1.45초 | 변경 후 1초 예약이므로 정상 |
| PDF | 1.1초, 4.5MB | 30초 이내 |
| 모양 그대로 PPT | 1.4초 | 30초 이내 |
| 편집용 PPT | 0.5초 | 30초 이내 |
| 발표 시작 | 49ms | |

배포 결과는 24MB다. 첫 화면에 필요한 스크립트는 1.45MB에서 756KB로 줄였고, 출력 도구(697KB)는 내려받을 때 불러온다.

## 점검 중 찾아 고친 결함

**결함 01. 보안 정책이 글꼴 일부를 막음**
- 현상: 보안 정책을 넣자 글꼴 약 200개 항목이 차단됐다.
- 원인: 빌드가 작은 글꼴 파일을 CSS 안에 `data:`로 넣었고 정책은 같은 주소의 글꼴만 허용했다.
- 영향: 그 글자 묶음이 대체 글꼴로 보이거나 출력이 실패했을 것이다.
- 수정: 글꼴을 CSS에 넣지 않게 빌드 옵션을 바꿨다. CSS도 1.2MB에서 478KB로 줄었다.
- 검증: 배포본 시험에서 보안 정책 위반 0건.

**결함 02. 하위 경로에 올리면 앱이 열리지 않음**
- 현상: `/canvacraft/` 아래에서 빈 화면이었다.
- 원인: 빌드 결과가 `/assets/...` 절대 경로를 썼다.
- 영향: 호스트 맨 앞 경로가 아니면 쓸 수 없었다.
- 수정: 상대 경로로 빌드한다.
- 검증: 모든 배포본 시험을 하위 경로에서 실행.

**결함 03. 망가진 작품을 열어도 아무 안내가 없음**
- 현상: 목록에서 망가진 작품을 누르면 아무 일도 일어나지 않았다.
- 원인: 이미 목록 화면이면 `Home`이 다시 만들어지지 않아 새 안내 문구를 버렸다. 원본 파일 열기 실패도 같았다.
- 영향: 왜 안 열리는지 알 수 없었다.
- 수정: 안내가 있을 때마다 목록 화면을 새로 그린다.
- 검증: "저장된 작품이 망가졌으면" 시험.

**결함 04. 화면 오류가 나면 빈 화면**
- 현상: 렌더 오류 시 흰 화면만 남았다.
- 원인: 오류 경계가 없었다.
- 영향: 아이가 복구 방법을 알 수 없었다.
- 수정: 안내와 새로고침 단추를 둔다.
- 검증: 오류를 일으켜 안내와 저장본 복원 확인.

**결함 05. 연결하지 않은 작업 중 자산이 배포에 포함됨**
- 현상: `backgrounds-illustrated` 2.1MB가 배포 결과에 들어갔다.
- 원인: `public` 전체가 복사된다.
- 영향: 쓰지 않는 AI 생성 그림을 공개하게 된다.
- 수정: 빌드 후 뺀다. 앱에 연결할 때 `scripts/prune-dist.mjs`의 그 줄을 지운다.
- 검증: `dist`에 없음.

**결함 06. 파일을 연 직후 저장 전인데 저장됨으로 표시**
- 현상: 원본 파일이나 템플릿을 열면 저장을 시작하기 전 첫 화면에 잠깐 `저장됨`이 보였다.
- 원인: 편집 화면의 저장 상태 기본값이 `saved`이고, 자동 저장이 효과 단계에서야 실제 상태를 알렸다.
- 영향: 저장 완료 때만 표시한다는 계약(§6)과 어긋난다. 그 순간 탭이 닫히면 저장됐다고 믿은 작품이 없을 수 있다. 시험 하나가 간헐적으로 실패해 발견했다.
- 수정: 저장하지 않은 문서는 첫 화면부터 `변경 있음`으로 시작한다.
- 검증: 표시 순서를 기록하는 시험(`home.spec.ts`)이 수정 전 실패, 수정 후 통과.
